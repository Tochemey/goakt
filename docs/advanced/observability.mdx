GoAkt provides built-in observability through metrics (system and per-actor), event streams, and dead letters. Metrics
are available as programmatic snapshots and, when configured, as OpenTelemetry instruments for integration with
dashboards and exporters.

## Overview

| Mechanism             | Purpose                                                                                    |
| --------------------- | ------------------------------------------------------------------------------------------ |
| **System metrics**    | Node-level statistics via `ActorSystem.Metric`                                             |
| **Per-actor metrics** | Actor-level statistics via `pid.Metric`                                                    |
| **Event stream**      | System and cluster events (lifecycle, membership, dead letters)                            |
| **OpenTelemetry**     | Metrics exported when `WithMetrics` is used                                                |
| **Tracing**           | Zero-instrumentation actor traces via [goakt-ebpf](https://github.com/Tochemey/goakt-ebpf) |

All metrics are local: they reflect the current node only. Metrics are point-in-time snapshots; values do not update
after the struct is returned.

---

## System metrics

`ActorSystem.Metric(ctx)` returns a `*Metric` struct with node-level statistics. Returns `nil` when the actor system is
not started.

| Field              | Type     | Description                                         |
| ------------------ | -------- | --------------------------------------------------- |
| `DeadlettersCount` | `int64`  | Total messages dropped to dead letters on this node |
| `ActorsCount`      | `int64`  | Total number of live actors on this node            |
| `Uptime`           | `int64`  | Seconds since the actor system started              |
| `MemoryUsed`       | `uint64` | Used memory in bytes (host)                         |
| `MemorySize`       | `uint64` | Total memory in bytes (host)                        |
| `MemoryAvailable`  | `uint64` | Available memory in bytes (host)                    |

```go
m := sys.Metric(ctx)
if m != nil {
    log.Printf("actors=%d deadletters=%d uptime=%ds",
    m.ActorsCount(), m.DeadlettersCount(), m.Uptime())
}
```

## Per-actor metrics

`pid.Metric(ctx)` returns an `*ActorMetric` struct with actor-level statistics. Returns `nil` when the actor is not
running. For remote actors, metrics are fetched via remoting; the same fields are available.

| Field                     | Type            | Description                                                                  |
| ------------------------- | --------------- | ---------------------------------------------------------------------------- |
| `ProcessedCount`          | `uint64`        | Cumulative messages processed (excludes PostStart; excludes stashed/dropped) |
| `ChidrenCount`            | `uint64`        | Number of direct child actors                                                |
| `RestartCount`            | `uint64`        | Cumulative restarts (supervision)                                            |
| `Uptime`                  | `int64`         | Seconds since actor started (resets on restart)                              |
| `LatestProcessedDuration` | `time.Duration` | Duration of the most recent message processing                               |
| `StashSize`               | `uint64`        | Current number of stashed messages                                           |
| `DeadlettersCount`        | `uint64`        | Messages sent to dead letters by this actor                                  |
| `FailureCount`            | `uint64`        | Cumulative failures (panics, errors triggering supervision)                  |
| `ReinstateCount`          | `uint64`        | Cumulative reinstatements (suspended → resumed)                              |
| `UnhandledCount`          | `uint64`        | Cumulative messages the actor rejected with `ReceiveContext.Unhandled`       |

```go
m := pid.Metric(ctx)
if m != nil {
    log.Printf("actors=%s processed=%d restarts=%d stash=%d",
    pid.Name(), m.ProcessedCount(), m.RestartCount(), m.StashSize())
}
```

## Event stream

The event stream publishes **system and cluster events** (lifecycle, membership, dead letters). It is separate from
application-level PubSub. See [Event Streams](/advanced/event-streams) for full documentation.

```go
subscriber, err := sys.Subscribe()
if err != nil {
    return err
}
defer sys.Unsubscribe(subscriber)

for msg := range subscriber.Iterator() {
    switch e := msg.Payload().(type) {
        case *actor.ActorStarted:
        // ...
        case *actor.Deadletter:
        // ...
    }
}
```

Event types: `ActorStarted`, `ActorStopped`, `ActorChildCreated`, `ActorPassivated`, `ActorRestarted`, `ActorSuspended`,
`ActorReinstated`, `Deadletter`, `NodeJoined`, `NodeLeft`.

---

## Dead letters

Messages sent to stopped or non-existent actors are captured by the dead-letter actor and published to the event stream.
The `Deadletter` payload includes sender, receiver, message, and reason. Subscribe to the event stream to observe or log
dead letters.

## OpenTelemetry

When `WithMetrics()` is passed at actor system creation, the framework registers OpenTelemetry observable counters. You
must initialize the OpenTelemetry SDK (MeterProvider, exporter) before starting the actor system; otherwise metrics are
not exported.

### System-level instruments

Attributes: `actor.system`.

| Instrument                      | Type                     | Description                     |
| ------------------------------- | ------------------------ | ------------------------------- |
| `actorsystem.deadletters.count` | Int64ObservableCounter   | Total dead letters on this node |
| `actorsystem.actors.count`      | Int64ObservableGauge     | Live actors on this node        |
| `actorsystem.uptime`            | Int64ObservableGauge (s) | Actor system uptime in seconds  |
| `actorsystem.peers.count`       | Int64ObservableGauge     | Connected peers (cluster mode)  |

### Actor lifecycle instruments

Attributes: `actor.system`, `actor.kind`.

These three totals count events that remove an actor from the tree, so they are reported by the actor system rather than
by a PID, one series per actor kind. System actors (guardians, the dead-letter actor, topic actors) are excluded.

| Instrument               | Type                   | Description                                    |
| ------------------------ | ---------------------- | ---------------------------------------------- |
| `actor.spawned.count`    | Int64ObservableCounter | Actors of this kind whose spawn completed      |
| `actor.stopped.count`    | Int64ObservableCounter | Actors of this kind that were shut down        |
| `actor.passivated.count` | Int64ObservableCounter | Actors of this kind that passivated            |

<Note>
  `actor.stopped.count` counts terminal stops only. The teardown a restart performs before re-initializing an actor is
  reported by `actor.restart.count`, and a passivation is reported by `actor.passivated.count`, so no lifecycle event is
  counted twice.
</Note>

### Per-actor instruments

Attributes: `actor.system`, `actor.name`, `actor.kind`, `actor.address` by default, or `actor.system` and `actor.kind`
under [`WithLowCardinalityMetrics`](#reporting-one-series-per-actor-kind).

Per-actor metrics are collected by a single callback that walks the actor tree on every scrape, so the number of meter
registrations stays constant regardless of the actor population. An actor appears in scrapes once it is running and has
processed its `PostStart` message; suspended, stopping, and passivating actors are omitted until they are running again.

| Instrument                     | Type                      | Description                         |
| ------------------------------ | ------------------------- | ----------------------------------- |
| `actor.children.count`         | Int64ObservableGauge      | Current child actors                |
| `actor.stash.size`             | Int64ObservableGauge      | Messages stashed                    |
| `actor.deadletters.count`      | Int64ObservableCounter    | Dead letters sent by this actor     |
| `actor.restart.count`          | Int64ObservableCounter    | Restarts                            |
| `actor.last.received.duration` | Int64ObservableGauge (ms) | Duration of last message processing |
| `actor.processed.count`        | Int64ObservableCounter    | Messages processed                  |
| `actor.uptime`                 | Int64ObservableGauge (s)  | Actor uptime in seconds             |
| `actor.failure.count`          | Int64ObservableCounter    | Failures                            |
| `actor.reinstate.count`        | Int64ObservableCounter    | Reinstatements                      |
| `actor.unhandled.count`        | Int64ObservableCounter    | Messages rejected with `Unhandled`  |

`actor.deadletters.count` carries one extra attribute, `message.type`, naming the type of the dropped message, and is
reported once per message type the actor dropped. An actor that has dropped nothing reports a single zero without the
attribute. To get an actor's total across all types, sum the series:

```promql
sum by (actor_name) (actor_deadletters_count)
```

### Reporting one series per actor kind

By default each instrument above produces one time series per live actor. That is precise, but the series count grows
with the actor population, which becomes expensive to store and query once a system runs thousands of actors.

`WithLowCardinalityMetrics` reports the same instruments once per actor kind instead. The scrape aggregates the live
actors of each kind and observes each instrument once, carrying only `actor.system` and `actor.kind`:

```go
sys, _ := actor.NewActorSystem("app", actor.WithMetrics(actor.WithLowCardinalityMetrics()))
```

The series count then depends on how many actor kinds the system declares, not on how many actors it runs. System
actors (guardians, the dead-letter actor, topic actors) are excluded from the per-kind series; they only appear in the
default per-actor mode.

<Warning>
  The per-actor attributes `actor.name` and `actor.address` are dropped in this mode, so an individual actor can no
  longer be singled out in a dashboard or an alert. Queries and alerts written against the default mode must be
  rewritten to group by `actor_kind`.
</Warning>

Each instrument is reduced across the live actors of the kind:

| Instrument                     | Reduction                     | Meaning per kind                                  |
| ------------------------------ | ----------------------------- | ------------------------------------------------- |
| `actor.children.count`         | sum                           | Children held by actors of this kind              |
| `actor.stash.size`             | sum                           | Stashed messages across the kind                  |
| `actor.restart.count`          | sum                           | Restarts across the kind                          |
| `actor.processed.count`        | sum                           | Messages processed by the kind                    |
| `actor.failure.count`          | sum                           | Failures across the kind                          |
| `actor.reinstate.count`        | sum                           | Reinstatements across the kind                    |
| `actor.unhandled.count`        | sum                           | Unhandled messages across the kind                |
| `actor.deadletters.count`      | sum per kind and message type | Drops by the kind, still broken down by type      |
| `actor.uptime`                 | max                           | Age of the oldest live actor of the kind          |
| `actor.last.received.duration` | min                           | Time since the kind last processed a message      |

<Note>
  The two time gauges cannot be summed. The maximum uptime answers how long the kind has been running, and the minimum
  time since the last received message answers whether the kind is still active.
</Note>

The gate is unchanged: only running actors that have processed their `PostStart` contribute, so a kind whose actors are
all suspended drops out of the series until one resumes. A kind that has dropped nothing reports a single zero for
`actor.deadletters.count` without the `message.type` attribute, exactly as an actor does in the default mode.

The system-level instruments and the actor lifecycle instruments already report one series per system and per kind, so
they are identical in both modes.

### Example

```go
import (
"go.opentelemetry.io/otel"
"go.opentelemetry.io/otel/exporters/otlp/otlpmetric/otlpmetrichttp"
"go.opentelemetry.io/otel/sdk/metric"
)

// Initialize SDK before creating actor system
exporter, _ := otlpmetrichttp.New(context.Background(), otlpmetrichttp.WithInsecure())
provider := metric.NewMeterProvider(metric.WithReader(metric.NewPeriodicReader(exporter)))
otel.SetMeterProvider(provider)

sys, _ := actor.NewActorSystem("app", actor.WithMetrics())
```

## Tracing

For **zero-instrumentation distributed tracing** of actor message flows, use [goakt-ebpf](https://github.com/Tochemey/goakt-ebpf). It runs as a sidecar process, attaches to your GoAkt v4 application via eBPF uprobes, and exports spans to any OTLP-compatible backend (Jaeger, Grafana Tempo, Honeycomb, etc.): no code changes or SDK dependency in your app.
