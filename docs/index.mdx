GoAkt is a distributed actor framework for [Go](https://go.dev/), inspired by Erlang and Akka. In development since 2022
and [used in production](/getting-started/production-usage), it lets you build responsive, resilient, and elastic
systems with typed actor messages, running as a single process or a cluster of nodes behind the same API.

## Why GoAkt

<CardGroup cols={2}>
  <Card title="Simpler concurrency" icon="inbox">
    Actors process one message at a time. You write plain Go with no locks, channel plumbing, or shared-state bugs.
  </Card>
  <Card title="Location transparency" icon="globe">
    Send a message to a local, remote, or clustered actor with the same API. The framework handles the wire.
  </Card>
  <Card title="Resilience by design" icon="shield-check">
    Supervision trees and the "let it crash" model, inspired by Erlang/OTP, keep failures contained and recoverable.
  </Card>
  <Card title="Batteries included" icon="battery-charging">
    Clustering, virtual actors (grains), CRDTs, streams, scheduling, passivation, and observability, without re-rolling
    them yourself.
  </Card>
</CardGroup>

Teams use GoAkt for event processing, IoT and edge workloads, real-time platforms, and distributed backends that would
otherwise need a message broker plus custom coordination code. See [Use Cases](/getting-started/use-cases) for the full
picture.

## New to the actor model?

Actors are isolated units of computation that share no memory. Each one has a mailbox, private state, and one message in
flight at a time. On a message, an actor can create more actors, send messages, or change how it handles the next one.
[Actor Model](/actor/actor-model) covers the concepts in depth, and Carl Hewitt, the father of the actor model,
[explains it in his own words](https://www.youtube.com/watch?v=7erJ1DV_Tlo).
