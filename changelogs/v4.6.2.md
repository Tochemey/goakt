# v4.6.2 - 2026-10-11

## Highlights

- **`PostStart` runs on a fully started actor.** The handler sees the actor in the tree and in the cluster registry.
- **A slow remote receiver no longer stalls its connection.** A full `BoundedMailbox` refuses the remote overflow and returns its credit.
- **Shutdown and restart keep their promises.** Every grain deactivates on shutdown, and an actor restart replays what a cancelled request had stashed.
- **Distributed data survives a restart.** Deletions are snapshotted, a restarted node's first deltas are not dropped, and `LWWRegister.Set` always wins over the value it replaces.
- **Documentation says what the code does.** The migration guide moved to the documentation site, and four pages state their limitations.

## Fixes

- **`PostStart` is delivered after the tree attachment and the registry write**, so a handler can rely on the actor's registry record ([#1451](https://github.com/Tochemey/goakt/pull/1451)).
- **A remote message refused by a full `BoundedMailbox` goes to dead letters with its credit returned** instead of blocking the connection's inbound dispatcher; local senders keep the blocking backpressure ([#1453](https://github.com/Tochemey/goakt/issues/1453), see `playground/issue-1453`).
- **The remote credit registry no longer grows behind a message parked in a priority mailbox** ([#1453](https://github.com/Tochemey/goakt/issues/1453)).
- **A grain refuses a new request with `ErrActorSystemNotStarted` once its system is stopping**, so the shutdown `PoisonPill` always runs and `OnDeactivate` is never skipped ([#1453](https://github.com/Tochemey/goakt/issues/1453)).
- **An actor restart replays the messages a `StashNonReentrant` request had stashed**, in order, after `PostStart`; a terminal stop drops them, and a `WithStashing` stash is left alone ([#1453](https://github.com/Tochemey/goakt/issues/1453)).
- **A CRDT snapshot saves the tombstones within their TTL**, so a node restored from it holds its own deletions again.
- **A restarted node's first CRDT deltas are no longer dropped as duplicates**: the message sequence starts at the node's start time.
- **The Replicator forgets a deleted key once its tombstone expires**, so memory no longer grows with every key ever deleted.
- **`LWWRegister.Set` stamps a write past the register's current timestamp when the given time is not later**, as Akka's default clock does; a write with an earlier timestamp now wins instead of losing on merge.

## Documentation

- **Migration guide and dispatcher tuning** are on the documentation site: [v3 to v4](https://docs.goakt.dev/reference/migration-v3-to-v4) and [tuning the dispatcher](https://docs.goakt.dev/actor/actor-system#tuning-the-dispatcher).
- **[Distributed data](https://docs.goakt.dev/advanced/distributed-data)** states that `WithMaxDeltaSize` has no effect, that coordinated writes are not acknowledged, and that node ID reuse after a restart and `ORMap.Remove` then `Set` are limitations.
- **[Remoting](https://docs.goakt.dev/advanced/remoting)** names any bounded mailbox as the mitigation for a slow remote receiver and notes the unbounded ask worker pool.
- **[Grain reentrancy](https://docs.goakt.dev/grains/reentrancy)** documents what a full bounded mailbox refuses during a pause and that late replies are dropped at debug level.
- **[Clustering](https://docs.goakt.dev/clustering/overview)** explains `WithMinimumPeersQuorum` as the only partition safeguard and what it does not stop.
