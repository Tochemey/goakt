# v4.4.2 - 2026-07-24

## ✨ Features

- **`WithSingletonSupervisor` configures singleton actor supervision** ([#1278](https://github.com/Tochemey/goakt/issues/1278)). Singletons previously used a fixed internal supervisor that could not be overridden. `SpawnSingleton` now accepts a caller-provided supervisor, which applies on whichever node hosts the singleton and survives delegation and relocation. A `RestartDirective` restarts the singleton in place; relocation still only happens when the host node leaves. Without the option, the default behavior is unchanged: stop on panics and internal errors.
- **TLS moves to the remote config.** TLS is now configured with `remote.WithTLS(*tls.Info)` on the `remote.Config`, alongside the other must-match wire settings. `actor.WithTLS` is deprecated but keeps working; the remote config takes precedence when both are set, and TLS is only validated when remoting is enabled. The standalone `client` package picks up the TLS settings from each node's `remote.Config` and can now connect to TLS-enabled clusters; since it only dials out, it uses the `ClientConfig` field of the `tls.Info` and ignores `ServerConfig`.
- **The partition hasher moves to the cluster config.** The hash function used to map registry keys to cluster partitions is now set with `ClusterConfig.WithPartitionHasher`, next to `WithPartitionCount`, the setting it jointly defines placement with. `actor.WithPartitionHasher` is deprecated but keeps working; the cluster config hasher takes precedence when both are set.
- **Per-actor init timeout with `WithInitTimeout`.** The actor initialization timeout, previously only settable system-wide via `WithActorInitTimeout`, can now be overridden per spawn. The override bounds the actor's `PreStart` hook on whichever node hosts the actor: it applies to local and remote spawns, child actors honor their own override and otherwise fall back to the hosting node's system-wide timeout, and it travels with cluster relocation so an actor keeps its configured init budget wherever it is placed. A non-positive duration is ignored.
- **Four new mailbox implementations**, all selectable through `WithMailbox`. Each is allocation free on the enqueue and dequeue paths and recycles consumed contexts back to the pool like the default mailbox, so `Tell` stays allocation free. The priority mailboxes keep producers off the heap by pushing onto a lock-free intake that the single consumer drains before each dequeue, so `Enqueue` is O(1) and never contends with the consumer.
  - **`NonBlockingBoundedMailbox`**: a lock-free bounded multi-producer, single-consumer ring. Its capacity is rounded up to the next power of two. It never blocks a producer; when full, `Enqueue` returns `ErrMailboxFull` and the runtime routes the excess message to the dead-letter stream.
  - **`UnboundedStablePriorityMailbox`**: orders messages by a `PriorityFunc` like `UnboundedPriorityMailBox`, but preserves arrival order among messages of equal priority.
  - **`BoundedPriorityMailbox`**: a `PriorityFunc`-ordered mailbox with a fixed capacity. When full, `Enqueue` returns `ErrMailboxFull` and the excess message is dead-lettered instead of blocking the producer.
  - **`BoundedStablePriorityMailbox`**: `BoundedPriorityMailbox` with stable ordering, so equal-priority messages keep their arrival order.

## 🔧 Fixes

- **Concurrent same-name spawns no longer create duplicate actors** ([#1277](https://github.com/Tochemey/goakt/pull/1277)). Goroutines racing any local spawn path with the same name could each create a live instance, leaving the loser with an unsupervised orphan. Local spawns of one identity are now serialized so a name yields exactly one PID; racing callers share the in-flight spawn's result.
- **Singleton idempotent success resolves the PID from the confirmed registry address** ([#1277](https://github.com/Tochemey/goakt/pull/1277)). When the name was already bound to the intended singleton, a second registry lookup could momentarily miss the record and surface `ErrActorNotFound` from a creation call. The PID is now resolved from the address already read while confirming the conflict.
- **Leader-delegated singleton spawns stay retryable during membership churn** ([#1277](https://github.com/Tochemey/goakt/pull/1277)). Transient conditions on the leader (no leader elected, engine not running, no member with the requested role) were serialized as terminal errors. They now map to `CODE_UNAVAILABLE`, so a `SpawnSingleton` issued during a rolling restart retries until the cluster settles.
- **Restart preserves the configured init timeout and retry count.** The stop path embedded in a restart reset an actor's init timeout and init max retries to their built-in defaults, so an actor configured with `WithActorInitTimeout` (or a per-spawn `WithInitTimeout`) or `WithActorInitMaxRetries` silently reverted to the default budget after any restart. These spawn-time settings are now left untouched on restart, matching how the user-supplied supervisor is preserved.
