# v4.5.6 - 2026-09-16

## ⬆️ Dependencies

- **Cluster engine upgraded to `github.com/tochemey/olric` v0.3.21** ([#1365](https://github.com/Tochemey/goakt/pull/1365)). The engine now builds on `hashicorp/memberlist` v0.7.0, which reports its metrics through `github.com/hashicorp/go-metrics` directly.

  memberlist v0.7.0 removes the compatibility shim that let it emit its metrics through the deprecated `github.com/armon/go-metrics` module, so that module has left the dependency graph. The `exclude` block that kept `go mod tidy` and `go get -u` away from the armon tags that resolve to the renamed module is gone from `go.mod`, and the `hashicorpmetrics` build tag that CI, lint and the unit-test script set to bypass the fallback has been removed. Memberlist gossip metrics now always reach the global `hashicorp/go-metrics` sink. An application that built GoAkt with `-tags=hashicorpmetrics` can drop the tag, and one that collected those metrics through an `armon/go-metrics` sink must register a `hashicorp/go-metrics` sink instead.

  memberlist v0.7.0 also hardens its wire path against malformed packets. A user message frame whose declared length exceeds `20 MiB` is rejected before the receiver allocates its buffer, a compressed message is discarded once it expands past `40 MiB` instead of decompressing into an unbounded buffer, an empty decompressed message is rejected instead of being indexed, and a node whose protocol version vector arrives truncated is skipped by the protocol check and has its versions left unset, instead of crashing the receiver with an index out of range. The cluster engine uses memberlist for membership and failure detection only and sends neither user messages nor push/pull user state, so the new limits constrain nothing GoAkt does; they close paths a malformed packet could take to exhaust a node's memory or crash it.
