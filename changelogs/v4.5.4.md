# v4.5.4 - 2026-09-07

## ⚡ Performance

- **Idle actors retain about 40% less heap.** A spawned, started, idle actor now holds about `1,268 B` of live heap instead of about `2,124 B`, in `13` heap objects instead of `18`. Dense deployments of many light actors are correspondingly cheaper to keep resident.

  | Measurement | Before | After | Change |
  |---|---|---|---|
  | Live heap per idle actor | `2,124 B` | `1,268 B` | `-40%` |
  | Live heap per idle long-lived actor (`WithLongLived`) | `1,966 B` | `1,110 B` | `-44%` |
  | Heap objects per idle actor | `18` | `13` | `-28%` |
  | Live heap for one million idle actors on one node | `1.98 GB` | `1.18 GB` | `-40%` |

  The reduction comes from six changes to the per-actor layout:

  - Spawn settings most actors never set (reliable delivery configuration, durable queues, singleton spec, role, metrics identity) moved off the PID into a companion allocated only when one of them is used.
  - The logger and event stream are looked up from the actor system on demand instead of being copied onto every actor.
  - The per-actor system-message mailbox is a sentinel-free inline queue, so an idle actor holds no control-plane node.
  - The default user mailbox is embedded in the PID instead of allocated as a separate heap object.
  - Watchers are held in a small slice instead of a map, which for the usual two watchers cost a header, a bucket group, and a copy of each watcher's ID.
  - The actor path is a thin view over its address instead of a struct that re-copied the host, port, name, system, and cached strings the address already holds.

  Actor semantics are unchanged: one message at a time, system messages ahead of user messages, and send order preserved. Throughput is unchanged, `Tell` remains allocation-free, and custom mailboxes set with `WithMailbox` are unaffected.

## 🔧 Fixes

- **Cluster membership events follow routing table convergence** ([#1331](https://github.com/Tochemey/goakt/issues/1331)). `NodeLeft` and `NodeJoined` are now published as soon as the cluster routing table converges on a membership change, derived from the converged member list rather than from the single rebalance epoch opened for that change. Previously, a departure whose epoch was superseded by a later routing table push surfaced only through the `30s` fallback timer, and a join in the same situation could go unreported until the next join. Rapid sequences are now announced in the order the converged member list implies: a node that joins and departs, or departs and restarts, before the table converges; and a member that departs, restarts at the same address, and departs again, whose second departure was previously lost. A join that never converges is announced after the same `30s` bound as a departure, and the wait is cancelled as soon as the event is announced or the actor system stops.

- **A transient cluster cleanup failure no longer shuts down a healthy node** ([#1337](https://github.com/Tochemey/goakt/issues/1337)). When DeathWatch failed to remove a dead actor's record from the cluster registry, it escalated the error to the system guardian, which stopped the whole ActorSystem. A transient registry error during a membership transition could therefore turn one node's departure into a cascading outage. DeathWatch now logs the failure, keeps running, and retries the removal up to `5` times with exponential backoff through the system scheduler. A record still present after the last retry is reported at error level, and no retry is attempted once the cluster engine is stopped or the system is stopping. Every other DeathWatch failure still escalates as before.

- **Actors and grains keep their role constraint through relocation and remote activation** ([#1334](https://github.com/Tochemey/goakt/issues/1334)). Actors spawned with `WithRole` and grains activated with `WithActivationRole` lost their role when recreated on another node, because `SpawnOn`, the grain cluster record, and the remote activation request did not carry it. All three paths now transport the role. Eager grain relocation honors it: a role-constrained eager grain is reassigned to the least-loaded surviving node that advertises its role, and is reported in `RelocationFailed` when no surviving node qualifies. Lazy grains remain unconstrained during relocation and have their role re-applied at the next activation.

- **Peer state replication honors the remoting protocol pin** ([#1343](https://github.com/Tochemey/goakt/issues/1343)). The peer state snapshot a node replicates to its peers during graceful shutdown was sent over the legacy unary remoting path regardless of the configured protocol pin. With `remote.WithProtocolPin(remote.ProtocolPinDuplex)`, every peer refused the connection, the leader found no snapshot, and the departing node's actors and grains were never relocated. The snapshot now travels through the actor system's own remoting client, on the same protocol-pinned control path as every other internal RPC.
