# Unreleased

## Highlights

- **Grain scheduling and one-way tell.** A grain can now receive a message once after a delay, at an interval or on a cron expression, and `TellGrain` can return as soon as the message is enqueued.
- **Sturdier crash recovery.** A node that dies during a rebalance is no longer missed, a node that comes back is no longer relocated, and a crashed node no longer keeps the names of its non-relocatable actors and grains.
- **Unambiguous actor names.** Concurrent spawns of one name leave one actor, addresses carry the full ancestor path, and same-named children under different parents no longer share a registry record.
- **Simpler networking and discovery.** A wildcard bind address listens on every interface, mDNS discovery is rebuilt on `hashicorp/mdns`, and every built-in discovery provider is documented.
- **Fewer dependencies.** Four modules are gone, and the library's retries now share one exponential backoff with jitter.
- **Distributed data that converges.** An `ORSet` peer no longer loses elements, anti-entropy repairs values that differ under equal versions and deletions a peer missed, and cross-datacenter replication keeps a batch until each datacenter has accepted it.
- **Compression on the default protocol.** `remote.WithCompression` now compresses duplex connections, which every current node uses, and closing a compressed connection is safe.
- **Streams that respect demand and clean up.** Every stage pulls only what its downstream asked for, a failing input fails the stream, nothing a stream started outlives it, and fan-out graphs can run more than once.

## Upgrade Notes

- **Clusters on mDNS discovery need a full restart.** The mDNS provider was rebuilt, and nodes on the old and the new provider do not discover each other, so stop the whole cluster and start it again rather than rolling the upgrade.
- **Clusters on any other discovery provider can be upgraded one node at a time.** The mDNS rebuild is the only change that rules out a rolling upgrade. While nodes on the previous version and on this one run side by side, expect the following. Each item clears once every node is upgraded.
  - **Deeply nested actors.** A node on the previous version cannot parse the address of an actor nested two or more levels deep, such as a grandchild, and rejects it with `address format is invalid`. Top-level actors and direct children are unaffected.
  - **Child lookups from another node.** An upgraded node registers a child actor under its qualified name (`parent/child`); a node on the previous version registers it under its bare name (`child`). A lookup from another node succeeds only with the key the child's host used. Top-level actors are unaffected.
  - **Concurrent spawns of one name.** A node on the previous version still publishes actors the old way, so two spawns of the same name at the same time may still both succeed when one of them runs on such a node. The one-actor-per-name guarantee holds once every node is upgraded.
  - **Grains on a stopping node.** A node on the previous version does not recognize the refusal of a stopping upgraded node, so its `GrainIdentity` or `GrainOf` call for a grain placed there returns an error instead of activating the grain elsewhere. Retrying succeeds once the stopping node has left.
  - **One-way `TellGrain`.** When the grain lives on a node running the previous version, that node ignores the one-way option and acknowledges after processing, so the call waits as it did before. Delivery itself is unaffected.
  - **Compression.** An upgraded node now compresses a duplex connection when both sides name the same codec. A node on the previous version that has `WithCompression` set starts compressing when it dials an upgraded node, and it keeps the previous version's unsafe close of a compressed connection until it is upgraded too.
  - **Distributed data anti-entropy.** The content hash and the deletions carried by anti-entropy are new optional fields. Between an upgraded node and a node on the previous version, anti-entropy follows the version rule it used before, so values that differ under equal versions and missed deletions are repaired only between upgraded nodes.
  - **Distributed data after a long absence.** The time from which a node knows every deletion is a new optional field of the anti-entropy digest. A node on the previous version sends none, so it never resolves the stale keys of a node back after the tombstone TTL; they are kept once every peer has been heard from. A snapshot written by the previous version has no last contact, so a node restored from it is treated as having no gap, as before.
  - **Refusals of a stopping grain owner.** An upgraded node marks on the wire a grain message it refused because it is stopping, and `TellGrain` and `AskGrain` send such a message again on a live node only when the mark is present. A node on the previous version does not mark its refusals, so a call that meets it returns `ErrSystemShuttingDown` and keeps its record, as before. A node on the previous version ignores the mark.
  - **Supervisor backoff on another node.** The backoff of a supervisor travels with an actor spawned on another node or relocated there. A node on the previous version ignores it and supervises without backoff, as before.

## Changes

### Features

- **Dispatcher pool size** ([#1400](https://github.com/Tochemey/goakt/issues/1400)). `WithDispatcherPoolSize` sets the size of the worker pool that runs actor and grain turns, which defaults to `max(GOMAXPROCS, 2)`. A handler that blocks in its turn, on a database call or a synchronous request, holds its worker for the whole wait, so with the default no more than GOMAXPROCS actors and grains make progress at once. A larger pool lets that many blocking handlers wait at the same time; one-at-a-time execution per actor and per grain is unchanged. The pool is shared by every actor and grain, so a pool much larger than `GOMAXPROCS` slows dispatch for handlers that do not block.
- **Cluster store directory** ([#1403](https://github.com/Tochemey/goakt/issues/1403)). `ClusterConfig.WithStoreDir` sets the directory a node keeps its cluster store in, the BoltDB file that persists its peer state. The default stays `~/.goakt/cluster`, which fails on a pod with a read-only root filesystem or in a sandbox without a home directory; point it at a writable volume there.
- **`AskGrain` and `TellGrain` release a stale grain owner record** ([#1435](https://github.com/Tochemey/goakt/issues/1435)). Before, only `GrainOf` and `GrainIdentity` released the record of an owner that was stopping or had left the cluster, so a bare send failed until something else released it. `AskGrain` and `TellGrain` now release it under the same rule. When the owner refused the message because it is stopping, the message did not run, and the same call sends it again to the grain activated on the calling node with the recorded configuration, within what is left of the call's timeout. The same happens when the owner left the cluster and the calling node could not even connect to it, since the request never left. When the owner left with the message in flight, the call returns the transport error without sending again, because the message may have run before the owner died; the next call reaches the grain on a live node. A call sends a message again at most once. An `ErrSystemShuttingDown` returned by a grain handler is not a refusal and keeps the record. The registry writes of a grain activation and of a release (the claim, the publication of the record and the release of an owner's entry) are now tried again a few times, because the registry can fail a write it still routes to a node that is leaving; before, a few hundred calls per million failed with `context canceled` during a rolling restart.
- **Watchers hear of deletions** ([#1436](https://github.com/Tochemey/goakt/issues/1436)). An actor subscribed to a CRDT key with `crdt.Subscribe` now receives `crdt.Deleted` carrying the key when its node removes its copy because of a deletion, whether the key was deleted on that node, on a peer or in another datacenter. A node that does not hold the key sends nothing, and each node announces a deletion once. The watcher stays subscribed and receives `Changed` again if the key is created after its tombstone has expired.
- **Grain options per kind** ([#1402](https://github.com/Tochemey/goakt/issues/1402)). `WithGrainDefaultOptions[*MyGrain](opts...)` on the actor system declares the options every grain of that kind is configured with. They apply under the options of a `GrainOf` call, under the options a registry record carries, and alone for a bare send that creates the grain. Before, the options belonged to the `GrainOf` call: a bare `AskGrain` or `TellGrain` that found the grain passivated reactivated it with the package defaults, and a grain activated on another node got the default idle timeout, so the safe pattern was `GrainOf` with the full option list before every send.
- **Message scheduling for grains** ([#1372](https://github.com/Tochemey/goakt/issues/1372)). `ScheduleGrainOnce`, `ScheduleGrain` and `ScheduleGrainWithCron` deliver a message to a grain once after a delay, at a fixed interval or on a cron expression. Delivery is a one-way `TellGrain` that reaches the grain wherever it lives and reactivates it if it has passivated. Grain schedules share references, `CancelSchedule`, `PauseSchedule`, `ResumeSchedule`, metrics and cluster rules with actor schedules, and `ListSchedules` reports them through the new `ScheduleInfo.Grain` field. They outlive the grain's activation and, like actor schedules, are not persisted.
- **One-way tell for grains** ([#1370](https://github.com/Tochemey/goakt/issues/1370)). `TellGrain` on the actor system and on `GrainContext` accepts `actor.WithOneWay()`, and `client.TellGrain` accepts `client.WithOneWay()`. The call returns once the message is enqueued; errors before the enqueue are still returned, and a handler failure or panic is recorded as a deadletter. Without the option the call waits for the acknowledgement as before.
- **mDNS discovery accepts a logger** ([#1368](https://github.com/Tochemey/goakt/issues/1368)). `mdns.NewDiscovery` takes `mdns.WithLogger`, which routes the provider's and the library's output to your logger. The default discards it.
- **Actor qualified name**. The new `actor.QualifiedName` function builds the name that identifies an actor within its actor system: the names of its ancestors from the root down, then its own, joined by `/`. `actor.QualifiedName("orders", "worker")` returns `orders/worker`, and a single name is returned unchanged. `ActorOf`, `ActorExists`, `Kill` and `ReSpawn` resolve that name, locally and in a cluster. Every name must pass the checks `Spawn` applies: the first one that fails them is reported with `ErrInvalidActorName`, or with `ErrReservedName` when it is reserved for system actors.
- **Qualified name of a running actor**. The new `QualifiedName` method on `Path` returns the same name for a running actor: `pid.Path().QualifiedName()` is `orders/worker` for a child and the actor's own name for a top-level actor.

- **Dial timeout for remoting.** `remote.WithDialTimeout` sets how long a node waits to open a TCP connection to a peer, five seconds by default. A dial to an address that drops packets, such as the IP of a departed Kubernetes pod, then fails on its own timeout instead of on the caller's deadline, which lets the sender recognize a departed grain owner and release its record.
- **Content hash for replicated data.** Every built-in CRDT type implements the new optional `crdt.StateHasher` interface: `StateHash` returns a hash that is equal for equal states, whatever the order of the operations that produced them.
### Fixes

- **`MergeSubstreams` holds its source back under a slow downstream** ([#1434](https://github.com/Tochemey/goakt/issues/1434)). The splitter behind `MergeSubstreams` collected the output of every substream in one buffer with no limit, and pulled the source at full speed, so a slow downstream made it hold everything the source produced that it did not drop. A million elements through four `GroupBy` keys into a blocked sink pulled the whole source, kept more than half a million elements and dropped the rest. Each substream now sends at most one demand window ahead of what the downstream has taken, and the splitter takes no element from the source while its merged buffer holds a window, so the same stream pulls under a thousand elements and drops none. `BackpressureSource` on `WithSubstreamBuffer` now does what it says: a substream at its in-flight cap holds the source back until it has room, where before it dropped like `DropTail`. See `playground/issue-1434`.
- **A node back after the tombstone TTL no longer brings deleted keys back** ([#1437](https://github.com/Tochemey/goakt/issues/1437)). A tombstone is pruned once it is older than `crdt.WithTombstoneTTL`, 24 hours by default. A node away for longer that still held a deleted key, restored from its CRDT snapshot or kept running through a partition, brought the key back: no node retained the tombstone, so anti-entropy treated its copy as a key the others lacked. Each Replicator now records the last time it heard from a peer, and saves it with its snapshot. When it hears from a peer again after a gap longer than the TTL, the keys it held before the gap and has not updated since are stale, and it does not send them to peers. A peer that was in the cluster for the whole gap resolves them: a stale key that peer holds is kept, one it does not hold was deleted during the gap and is removed. When no current peer was there for the whole gap, as after a restart of the whole cluster, the stale keys are kept once every peer has been heard from. Two groups of nodes that run apart for longer than the TTL still bring back each other's deleted keys when they merge. See `playground/issue-1437`.
- **An actor no longer handles asks whose sender stopped waiting** ([#1430](https://github.com/Tochemey/goakt/issues/1430)). The actor counterpart of [#1407](https://github.com/Tochemey/goakt/issues/1407). The timeout of `Ask` was a timer on the sender's side only: an ask that waited in the mailbox or in the stash past its timeout was still handed to `Receive`. The actor now skips an ask it dequeues after its sender stopped waiting, the ask timeout or the deadline of the sender's context when that comes first, and `ReceiveContext.Context()` ends at that moment. Before, the context carried a deadline only when the sender's own context had one or the ask came from another node. An ask already in `Receive` when its sender gives up still runs to the end. Tells are unchanged. See `playground/issue-1430`.
- **A timed out `Ask` to an actor on another node returns `ErrRequestTimeout`** ([#1430](https://github.com/Tochemey/goakt/issues/1430)). `Ask` and `BatchAsk` against a remote actor returned only the transport error, `context deadline exceeded` or an i/o timeout, so `errors.Is(err, ErrRequestTimeout)` was false although it is true for a local actor and for a grain. The error now carries `ErrRequestTimeout` as well.
- **A grain no longer handles asks whose sender stopped waiting** ([#1407](https://github.com/Tochemey/goakt/issues/1407)). The timeout of `AskGrain` was a timer on the sender's side only. An ask that waited in the mailbox past its timeout was still handed to `OnReceive`, so a slow grain spent its turns on answers nobody read, and a sender that timed out and retried had its work done twice. The grain now knows when the sender of an ask stops waiting, the ask timeout or the deadline of the sender's context when that comes first, and skips an ask it dequeues after that moment. The same moment is the deadline of `GrainContext.Context()`, so a handler that passes the context to its database or HTTP calls stops when nobody waits. Before, the context carried a deadline only when the sender's own context had one, and never for a grain with reentrancy. This holds for a grain on the calling node or on another one, with or without reentrancy. An ask already in `OnReceive` when its sender gives up still runs to the end, so handlers whose callers retry must stay idempotent. Tells are unchanged. See `playground/issue-1407`.
- **`Stop` no longer fails when the listed peers are leaving too** ([#1415](https://github.com/Tochemey/goakt/issues/1415)). A stopping node hands its actors and grains to its peers before it leaves the cluster. When nodes stop one after another, the last one can still list peers that stopped a moment ago, and those answer `remoting is not enabled` or `cluster is not enabled` on a connection left open, or refuse a new connection. `Stop` counted these as failures and returned `failed to replicate state to any peer`, although no node was left to take the state. Such peers are now recognized as leaving. The handover still goes to the three oldest peers first; when all three are leaving, it moves on to the next oldest ones, so a younger node that keeps running still gets the state. Only when every listed peer is leaving is the handover skipped with a warning, and `Stop` succeeds, as it does for a node with no peers. A peer that does not answer in time, or that fails to store the state, still fails the handover and `Stop` still reports it.
- **`Stop` no longer fails when nodes stop together** ([#1415](https://github.com/Tochemey/goakt/issues/1415)). A stopping node removes the records of its actors and grains from the cluster registry, which is spread over the nodes. The removal of a record fails when the node holding it is gone or is stopping at the same time, and `Stop` returned that error: `context canceled`, `connection refused`, a registry timeout, or `grain deactivation failed` for every grain. Stopping a whole three-node cluster at once failed `Stop` on about half of the nodes. A record that stays behind names a node that has left, and the cluster already handles such records, as it must after a crash: lookups skip them, the next spawn of the name replaces them, and so does the recreation of a relocated actor or the next activation of the grain. The removal is now best effort: a failure is logged as a warning and `Stop` succeeds. See `playground/issue-1415`.
- **A failed cluster shutdown no longer leaves the node marked as clustered** ([#1415](https://github.com/Tochemey/goakt/issues/1415)). When a step of leaving the cluster failed, the stopped node kept its cluster flag set and kept its relocation bookkeeping. Both are now cleared whatever the steps return; the error is reported as before.
- **Crash recovery no longer outlives a stopped node** ([#1413](https://github.com/Tochemey/goakt/issues/1413)). The leader recovers a crashed node on a goroutine that retries a failed attempt after a five second backoff. It only learned of a shutdown from a flag that `Stop` clears again once it is done, so a recovery that slept through the shutdown, or polled past a fast one, carried on against the stopped cluster and logged its remaining attempts for up to twenty seconds after `Stop` had returned. It now recognizes a stopped system at every checkpoint, before it reads the cluster, and returns.
- **A node that crashes, rejoins and crashes again is recovered** ([#1413](https://github.com/Tochemey/goakt/issues/1413)). When a crashed node came back at the same address while the leader's crash recovery was still waiting, the recovery gave up, as it should, but also dropped the node's remoting port from the leader's cache, where the node's rejoin had just refreshed it. The next crash of that node could then not be recovered: every attempt failed with `no cached remoting port` and its actors and grains were never recreated. The recovery now keeps the cache entry of a node that rejoined, whether it sees the node back or the node rejoins while the recovery completes: before the entry is dropped for good, the membership is read once more.
- **A remote reply is decoded with its own serializer** ([#1411](https://github.com/Tochemey/goakt/issues/1411)). An ask to an actor or a grain on another node decoded the reply with the request's serializer, so a target that answered a CBOR request with a proto message, or the other way round, failed the caller with a decoding error while the same ask worked locally. This affected `AskGrain`, `RemoteAsk` and `RemoteBatchAsk`. The request's serializer still decodes the reply first, so asks that worked are unchanged; when it cannot, the reply is decoded the way the receiving node decodes requests, by trying every registered serializer.
- **Grain send failures keep their sentinels across nodes** ([#1409](https://github.com/Tochemey/goakt/issues/1409)). A send to a grain on another node that fails because its bounded mailbox is full, because it did not answer in time, or because it is no longer alive now returns `ErrMailboxFull`, `ErrRequestTimeout` or `ErrDead` on the calling node, as it does for a local grain, instead of an untyped internal error carrying their text. The owning node reports these outcomes at debug level; before, every one of them was an error log line.
- **An actor handles `PostStart` before any other message** ([#1422](https://github.com/Tochemey/goakt/issues/1422)). `PostStart` travelled through the user mailbox while `Terminated` and the other system messages take a priority queue, so a child that stopped before its parent's first turn delivered its `Terminated` first. The user guardian, parent of every top-level actor, sets its logger on `PostStart` and panicked on that `Terminated`, and the root guardian then shut the whole actor system down; a `Kill` or `ReSpawn` right after `Start` was enough to trigger it on a busy machine. `PostStart` now waits in a slot of its own that every turn checks before both queues, so it is the first message of every incarnation, after a spawn and after a restart, and nothing that reaches the actor in the meantime, system message or not, runs ahead of it. The check adds no measurable cost in the processing benchmarks.
- **A stopped actor frees its name before the stop returns** ([#1423](https://github.com/Tochemey/goakt/issues/1423)). `Kill` returned once the actor had run `PostStop`, but the name stayed in the local actor tree until the death watch handled the actor's `Terminated` in a later turn. A `Spawn` of the same name in that window started a new actor that nothing managed, and returned the stopped one with no error; the name then resolved to nothing. `ActorOf` and `ActorExists` also still found the stopped actor, and a `SpawnChild` after `Stop` returned a child its parent did not list. The stopping actor now leaves the tree and the live actor count itself before the stop returns, and the death watch only removes its cluster registry record. An actor whose `PostStop` fails is released the same way and its watchers are told, where before its name stayed taken for good. In cluster mode, a spawn on the same node writes over the record the stopped actor left, fenced by that actor's incarnation, instead of failing with `ErrActorAlreadyExists`.
- **Spawning a name held by an actor that is not running no longer starts a second actor** ([#1423](https://github.com/Tochemey/goakt/issues/1423)). `Spawn`, `SpawnNamedFromFunc`, `SpawnSingleton` and `SpawnChild` returned the existing actor only when it was running. When the name was held by a suspended actor, or by one that was stopping or restarting, they started a new actor, could not register it because the name was taken, and returned the existing one with no error; the new actor kept running with nothing to stop it. They now return `ErrActorAlreadyExists` and start nothing. Reinstate, restart or stop the actor that holds the name, then spawn again.
- **A restart keeps its names and registry records** ([#1423](https://github.com/Tochemey/goakt/issues/1423)). A restart tears the actor and its children down before starting them again. That teardown was reported to the death watch as a death, so the registry records were removed and written again, and the name was briefly free: another node could claim it in between, and a removal handled late could delete the record of the actor that had just restarted. The restarted actor and its children now keep their names and their records for the whole restart, and the records are updated in place.
- **Shutdown reaches a grain whose bounded mailbox is full** ([#1405](https://github.com/Tochemey/goakt/issues/1405)). The shutdown `PoisonPill` now goes into a grain's mailbox past its capacity, so a grain busy under backpressure handles the messages queued before the pill, runs `OnDeactivate` and stops like any other. Before, the pill was rejected with `ErrMailboxFull`, the grain was dropped without `OnDeactivate`, its queued messages were never handled and `Stop` returned the error. A grain that never finishes its current message is still cut off by the shutdown context. `Stop` now also names every grain whose `OnDeactivate` failed in its error; before, that failure was only logged.
- **Grain passivation waits for the message in progress** ([#1397](https://github.com/Tochemey/goakt/issues/1397)). A grain without reentrancy was deactivated as soon as it was idle past its timeout, even while `OnReceive` was still handling a message, and the next message started a second instance while the first was still running. Passivation now always runs on the grain's own turn, after the message in progress, and is skipped while messages are waiting in the mailbox. A message that reaches the grain while it deactivates is no longer handed to the deactivated instance: it is sent to a fresh activation, and its caller gets the reply from it. During a shutdown it is refused with `ErrSystemShuttingDown` instead.
- **A node that is shutting down no longer takes new grains** ([#1396](https://github.com/Tochemey/goakt/issues/1396)). A stopping node kept accepting grain activations until the end of its shutdown, and the registry record of a grain activated late outlived the node, so `GrainIdentity`, `GrainOf`, `TellGrain` and `AskGrain` failed with `remoting is not enabled` for that grain. A stopping node now refuses new activations with `ErrSystemShuttingDown` while it keeps serving the grains it already has active, and `GrainIdentity` and `GrainOf` activate the grain on a live node instead. When `GrainIdentity` or `GrainOf` finds that the recorded owner answers it is shutting down or has shut down, it releases the owner's record right away rather than after a transport failure. `TellGrain` and `AskGrain` with an identity obtained earlier do not release a stale record.
- **A crashed node no longer keeps the names of its non-relocatable actors** ([#1386](https://github.com/Tochemey/goakt/issues/1386)). When a node died without a shutdown, the registry records of its non-relocatable actors and grains survived it. Both are now released. Neither kind is recreated by the framework; only names and entries are freed.
  - **Actors.** An actor spawned with `WithRelocationDisabled` kept owning its name: `ActorOf` and `ActorExists` answered with the dead node, and a fresh spawn of the name failed with `ErrActorAlreadyExists`. The leader now releases those claims once crash recovery confirms the node is gone, and a spawn that meets such a claim writes its own record over it after checking that its holder is no longer a cluster member. Both are fenced by the actor incarnation, so a name a newer actor already claimed is never removed or written over.
  - **Grains.** A grain activated with `WithGrainDisableRelocation` had the same leak: its directory entry outlived the node until the next `GrainIdentity` call, and `TellGrain` and `AskGrain` failed against the dead node in the meantime. Crash recovery now releases that entry too, so the next message re-creates the grain on a live node.
  - **Lookups.** `ActorOf`, `ActorExists` and `Kill` apply the same membership check, so a non-relocatable actor on a departed node reports not found even before the leader releases its claim. Relocatable actors and singletons, which come back under the same name, stay resolvable while they are recreated.
  - **Convergence window.** While the cluster converges after the node loss, a registry read that runs out of its internal timeout while the caller's context is still alive now returns the new `ErrClusterRegistryTimeout`, which still matches `context.DeadlineExceeded`, so callers can tell it from their own deadline. In that window the registry also refuses to delete a record while a copy of it lives on the departed node, so a spawn that had to delete the dead node's claim first failed with `ErrActorAlreadyExists` while `ActorOf` already reported the actor as not found ([#1391](https://github.com/Tochemey/goakt/issues/1391)). The spawn now writes its own record over the claim instead, and a publication refused because another incarnation owns the name no longer takes the name's lock to find that out.
- **Crash recovery no longer misses a node that died during a rebalance** ([#1387](https://github.com/Tochemey/goakt/pull/1387)). The cluster engine defers `NodeLeft` until the routing table has converged on the departure. A rebalance epoch that started before a crash and completed after it still listed the dead node with a newer generation, so the engine took the departure for a restart, dropped it for good and never announced `NodeLeft`: nothing on that node was recovered, and the leader logged only `dropping stale departure`. The engine now checks the current membership before dropping such a departure. A member's is a stale copy and is dropped as before; a non-member's stays pending until the next convergence without it, or the bounded wait, announces it.
- **Concurrent spawns of one name leave one actor** ([#1377](https://github.com/Tochemey/goakt/issues/1377)). Two nodes spawning the same name at once could both succeed and keep two live actors, and stopping either deleted the other's registry record. The first spawn now wins, the others fail with `ErrActorAlreadyExists` and leave nothing behind, and a registry record is updated or removed only by the actor that owns it, so a stopped or rolled-back copy never touches the live one. A spawn costs what it did before, and concurrent spawns of different names on one node complete about three times faster because publishing no longer holds the node's registry write lock; the new `BenchmarkClusterSpawn` measures both.
- **Actor addresses carry the full path** ([#1379](https://github.com/Tochemey/goakt/issues/1379)). An address now renders every ancestor of the actor, `goakt://system@host:port/grand/parent/name`, and parses it back, as documented. Only the immediate parent used to be written, so two actors nested under same-named parents shared one address and the second `SpawnChild` returned the first actor. Top-level actors and direct children keep the addresses they had. Large-message destination patterns see the full path, one `*` per segment.
- **Same-named children no longer overwrite or delete each other's records** ([#1380](https://github.com/Tochemey/goakt/issues/1380)). Two children with the same name under different parents used to share one registry record and one local name entry: the second spawn replaced the first, and stopping either deleted the other's record while it was still running. Registry records are now keyed by the qualified actor name, the ancestor names and its own joined by `/` (`p1/kid`), and the local name index keeps every named actor. Top-level lookups are unchanged. A child is found by its qualified name from any node (`ActorOf(ctx, "p1/kid")`) and by its bare name on its own node, which returns the most recently spawned child of that name; a bare-name lookup from another node returns not found. Spawning a top-level actor with the name of a running child now creates the actor, and `Reinstate` of a child finds that child.
- **Crash recovery no longer relocates the actors and grains of a node that came back** ([#1383](https://github.com/Tochemey/goakt/issues/1383)). When a node left without a shutdown snapshot, the leader waited for the partition repair to go quiet and relocated whatever the registry still listed for it, without checking that the node was still gone. A transient departure, such as a failed and retried bootstrap, had the node rejoin at the same address, keep its actors and grains, and see them relocated anyway, leaving two live instances of each. The leader now checks the membership after the wait and again before dispatching the relocation set, and skips the recovery with a warning when the node is a member again. A node that really crashed is recovered as before.
- **etcd discovery validates `Timeout`.** A zero `Timeout` is rejected at validation instead of failing every request at runtime, in line with `DialTimeout` and `TTL`.
- **A wildcard bind address listens on every interface** ([#1374](https://github.com/Tochemey/goakt/issues/1374)). `remote.NewConfig("0.0.0.0", port)` used to bind the remoting server to one guessed private IP, so connections through loopback or any other interface were refused, and start failed on a host with no private or public address. The server now listens on the wildcard as configured, `::` serves IPv4 and IPv6 peers, and a host with no other address advertises loopback. What peers are told is unchanged: `ActorSystem.Host()`, actor addresses and cluster membership still advertise the first private IP, and cluster gossip and the registry still bind it. Bind a concrete IP to listen on one interface only.

- **A stopped node stops answering on connections it had open** ([#1396](https://github.com/Tochemey/goakt/issues/1396)). A stopped node kept serving connections that were already open and answered asks with `CODE_UNAVAILABLE: tcp: worker pool is stopped`, which the sender did not recognize, so the registry record of a grain on that node was never released and every send to it failed until the process exited. A stopping node now lets the asks it already took reply, refuses later ones with `ErrRemotingDisabled`, and then closes its connections. The sender releases the stale record and activates the grain on a live node in the same `GrainOf` call.
- **An error answered over a duplex connection keeps its sentinel.** An error reply on the duplex protocol, the default between current nodes, reached the caller as a plain string, while the same reply on the legacy protocol decoded to `ErrRemoteSendFailure`, `ErrRemotingDisabled`, `ErrMailboxFull` and the other sentinels. Both protocols now decode it the same way, and an ask whose connection closes under it fails with a transport error instead of an empty `CODE_INTERNAL` error.
- **A stopping node no longer publishes a grain record** ([#1396](https://github.com/Tochemey/goakt/issues/1396)). A grain recreated on a node that was stopping could have its registry record written after the shutdown had released it, so the record named a node that no longer had the grain.
- **A grain is reachable only once its record is published** ([#1396](https://github.com/Tochemey/goakt/issues/1396)). An activation whose registry publication failed rolled the grain back with `OnDeactivate` while a message that had reached it in between could still be in `OnReceive`. A message now waits for the activation to complete, and a failed activation is never seen by a sender.
- **`ORSet` peers no longer lose elements.** A delta named a node's whole counter but listed only the elements changed since the last delta, so a peer dropped that node's earlier elements, and the next full-state exchange removed them at the origin too. Two consecutive adds by one node were enough. A delta now carries every live element of each node it touches, and an element added and removed in one update is no longer sent to peers.
- **Anti-entropy repairs values that differ under equal versions.** Versions count local events and cannot be compared across nodes, so two nodes holding different values at the same version never exchanged them. The digest now carries a content hash per key, and state is exchanged whenever the hashes differ. A merge that changes nothing no longer bumps the version or notifies watchers, so a duplicate delivery counts once.
- **Anti-entropy repairs deletions.** A node that missed a deletion was never told of it, and after the tombstone expired anti-entropy brought the key back. Live tombstones now travel in both directions of the exchange; when two nodes deleted a key independently, the later deletion is kept.
- **Cross-datacenter replication keeps what it has not delivered.** The leader emptied its buffer before sending, so a batch that reached no datacenter was lost, and the buffers of other nodes grew with every update. Each node now keeps one pending entry per key, each datacenter is sent only what it has not accepted, and an entry is dropped once every datacenter has it. A key deleted and created again while the deletion was pending is no longer deleted again on the receiving datacenter.
- **`crdt.Changed` carries its key**, and a coordinated read of a key the node did not know no longer breaks its snapshots, the one taken at shutdown included.
- **Compression applies to duplex connections.** The remoting server always answered "no compression" in the duplex handshake, so `remote.WithCompression` compressed only legacy connections. It now answers the codec it is configured with; both sides must name the same one, and a mismatch keeps the connection, uncompressed. Closing a compressed connection while a read or a write is in progress no longer panics or hangs, and a dialer rejects a handshake reply that names a codec it did not propose.
- **A panic is supervised by the type of the error it carries.** A rule for a user error type never applied when the actor panicked with that error, and the default `PanicNilError → Restart` rule never fired, so `panic(nil)` stopped the actor. A panic with an error is now matched like `ctx.Err` with that error.
- **A restart keeps what the actor had.** Restarting a running actor told its watchers it had terminated, dropped what it watched, reset its restart count to one, lost its dependencies and reported an uptime counted from 1970. A supervised restart also ran `PreStart` again without `PostStop`. Both kinds of restart now run `PostStop` then `PreStart` and keep the mailbox, the watches, the dependencies and the counters. `Restart` of a stopped actor puts it back in the tree under its parent, and a restart that fails for good tells the parent.
- **`Terminated` reaches every watcher, after the name is free.** It now arrives once the dead actor's name can be spawned again, reaches a watcher that is suspended, and reaches watchers on other nodes. A remote watch, unwatch or reinstate of a child actor resolves it, and a node leaving no longer drops the watches of other nodes that share its IP.
- **Passivation no longer races its actor.** An attempt that found the actor busy made it refuse messages and look dead to its parent; a `Shutdown` racing an attempt ran `PostStop` twice; a message accepted just before an attempt could be dropped; a deadline could fire up to 100 ms early; and a deadline expiring during `Stop` made `Stop` hang. A zero eviction interval no longer crashes the process, and routers no longer passivate after two idle minutes.
- **The scheduler survives its start context.** Cancelling the context passed to `Start` stopped the scheduler while new schedules were still accepted. A fired one-shot now releases its reference, a rejected duplicate reference no longer replaces the listed target, and a paused one-shot can be resumed.
- **Routers route as documented.** Round robin rotates in spawn order, fan-out keeps each routee's order, a routee that stopped by itself is skipped instead of losing the message, growing the pool after a removal adds as many routees as asked, and scatter-gather and tail-chopping no longer block the router while they wait.
- **Topics and the event stream.** Concurrent `TopicStats` on several nodes no longer time out, a topic is removed with its last subscriber, and an event-stream subscriber can no longer lose a message or spin under concurrent publishers.
- **Metrics and logging.** `ProcessedCount` no longer reads 2⁶⁴−1 before `PostStart`, the dead-letter count is refreshed on every scrape, metric callbacks are unregistered on `Stop`, Zap error lines carry their stack trace, and a file-backed Zap logger keeps flushing after its first `Flush`.
- **Reliable delivery reports a failed load once.** `ReliableDeliveryFailed` with stage `Load` was published once per `PreStart` retry, during a first spawn too. It is now published once per failed restart and never during a first spawn. A data race on the work-pulling controller's generation is fixed.
- **Streams respect downstream demand.** Fused stages, `ParallelMap`, `OrderedParallelMap`, `FromChannel` and fan-in inputs pulled ahead of demand without bound; they now pull only what their downstream asked for, a fan-in input at most one window ahead. A fan-in with as many fast inputs as dispatcher workers no longer freezes the whole actor system. `Batch` emits batches of at most `n`, keeps its last partial batch and fills by size for any `n`.
- **Stream failures and cleanup.** A failing or unbuildable input of `Merge`, `Concat`, `Zip`, `Combine` or a `Merge…` variant, of a substream or of a `SourceRef` producer now fails the stream instead of looking like completion or hanging. The coordinator actor stops with its stream, a sink crash stops the remaining stages, and inputs, nested streams, substreams and a `SourceRef` source stop with the stream, even when it is aborted right after `Run`. A `First` sink reports an upstream error.
- **Stream builders and fan-out.** Every `With…` call on a stage now applies, in any order; before, only the first one did, and the stage lost its actor system, metrics and default name. `Broadcast`, `Balance`, `Partition` and Graph DSL fan-outs can run more than once, `Stop` on a `Broadcast` branch returns, and an aborted branch no longer stalls its siblings. A stage with an error strategy other than fail-fast, or with a tracer, is no longer fused away.
### Behavior Changes

- **Substream buffers default to `BackpressureSource`** ([#1434](https://github.com/Tochemey/goakt/issues/1434)). A substream slower than the source that feeds it now holds the source back, and with it every other substream, instead of dropping its new elements. Pass `WithSubstreamBuffer(n, stream.DropTail)` to keep dropping. A slow downstream holds the source back under every strategy, so `DropTail` and `FailSource` no longer drop or fail because of it; they apply only while the downstream asks for elements. A key that carries most of the elements can still reach the cap in bursts while the downstream keeps up, so `DropTail` drops some of its elements and `FailSource` can fail, far less often than before.
- **The context of an ask ends with the ask** ([#1407](https://github.com/Tochemey/goakt/issues/1407)). For a message sent with `AskGrain`, `GrainContext.Context()` now ends at the ask deadline and when `OnReceive` returns; after `DeferResponse` it ends at the deadline only. For a message sent to an actor with `Ask`, `ReceiveContext.Context()` ends at the ask deadline and when `Receive` returns. A handler that hands this context to work that outlives the ask, a goroutine it starts or a `PipeTo` task, must detach it with `context.WithoutCancel`. The context of a tell is unchanged.
- **`Stop` no longer reports a failed registry removal** ([#1415](https://github.com/Tochemey/goakt/issues/1415)). An error removing the stopping node's actor and grain records from the cluster registry is logged as a warning instead of being returned. A grain that is deactivated while its node keeps running still reports a failed removal. Errors from leaving the cluster and from closing the cluster store are still returned, and so is a failed handover of the node's state to a peer that is not leaving itself.
- **`PostStart` no longer goes through the mailbox** ([#1422](https://github.com/Tochemey/goakt/issues/1422)). It is delivered from its own slot, so a full bounded mailbox can no longer refuse it, a custom mailbox never sees it, and it no longer counts towards the `actor.mailbox.size` metric. During a restart, the new incarnation's `PostStart` now runs as soon as any message reaches the actor, which can be before its children have been restarted; before, it was delivered only once the children were back. A `PostStart` handler that uses its children should look them up rather than assume they are running.
- **A failed restart stops the whole subtree** ([#1423](https://github.com/Tochemey/goakt/issues/1423)). When `Restart` or `ReSpawn` fails, because `PreStart` returns an error or a child cannot be restarted, every actor of the subtree is now stopped, its watchers receive `Terminated`, and its name and registry record are released. Before, the subtree could be left partly recovered: children restarted before the failure kept running under a parent that was not, and the failed actor could keep its name.
- **A stop directive no longer reports a dead sibling as suspended** ([#1423](https://github.com/Tochemey/goakt/issues/1423)). With a one-for-all stop directive, a sibling whose `PostStop` failed was marked suspended and an `ActorSuspended` event was published for it, although it was dead. It is now simply stopped, and its name is free.
- **CRDT watchers receive `crdt.Deleted`** ([#1436](https://github.com/Tochemey/goakt/issues/1436)). A subscribed actor that does not handle the new message treats it like any other message it does not handle, as it would a `Changed`.
- **Watchers are told when `PostStop` fails** ([#1423](https://github.com/Tochemey/goakt/issues/1423)). An actor whose `PostStop` returned an error, or whose children failed to stop, used to be marked as stopped without sending `Terminated` to its watchers. They now receive it. `Shutdown` and `Kill` still return the error.
- **A node that is shutting down refuses grain requests it can no longer honor** ([#1396](https://github.com/Tochemey/goakt/issues/1396), [#1397](https://github.com/Tochemey/goakt/issues/1397)). From the moment a node starts shutting down, it no longer activates grains, and messages still queued behind a grain's deactivation are no longer handed to the deactivated grain. Both are refused with `ErrSystemShuttingDown`. Before, such calls appeared to succeed, but some were handled by a grain that was about to be dropped or had already run `OnDeactivate`, so their effects could be lost. During a rolling restart, callers may therefore see a few `ErrSystemShuttingDown` errors per restarting grain. The message was not processed, so it is safe to send it again; in a cluster the retry reaches the grain on a live node.
- **mDNS discovery rebuilt on `hashicorp/mdns`** ([#1368](https://github.com/Tochemey/goakt/issues/1368)). Each node registers its own instance name and carries the cluster name in its TXT record; configuration is unchanged. Peers learn one IPv4 address and, with `IPv6` set to true, one IPv6 address per node; IPv6-only networks are not supported. See the upgrade notes above.
- **Sorted results where the order used to be unspecified.** Kubernetes, mDNS and DNS-SD peer addresses (deduplicated), `Peer.Roles` and `ActorSystem.Grains` now come back sorted.
- **Retry delays follow a new curve.** Every retry that ran on `flowchartsman/retry` now runs on `cenkalti/backoff`: spawn, initialization, grain activation, supervised child restart, routee restart, relocation, reliable delivery, shutdown hooks, remote stream endpoint resolution and NATS discovery. Delays double with up to fifty percent jitter within the same bounds; where a retry's bounds are equal the delay stays fixed and only gains jitter. Attempt counts, defaults and returned errors are unchanged.

- **Supervision matches a panic's error.** A panic with an error now follows the rule for that error's type, then the `PanicError` rule, then the any-error rule; before, only the `PanicError` rule applied. `panic(nil)` follows the `PanicNilError` rule, which restarts by default.
- **Restarts run `PostStop` and keep state.** A supervised restart and `Restart` both run `PostStop` before `PreStart`, keep watches, dependencies and counters, and do not tell watchers `Terminated`.
- **Round robin rotates in spawn order** instead of an unspecified order.
- **A retried stream stage makes 1 + `MaxAttempts` calls**, whatever the order of `WithErrorStrategy` and `WithRetryConfig`; before, the retry configuration was ignored when set after the strategy.
- **`FromChannel` reads only against demand.** A producer writing to the channel now blocks until the stream asks for more, and a closed channel is noticed when the stream next asks.
- **A failing fan-in input fails the stream**, discarding what was buffered; before, it was treated as that input completing.
- **`Stop` counts a peer that closes the connection as leaving.** During the state handover, a peer that closes the connection under the request is now treated like one that refuses it, so `Stop` no longer fails because a peer was stopping at the same moment.
### Deprecations

- **Kubernetes discovery: `RemotingPortName` and `PeersPortName`.** Both fields are deprecated and ignored; peers learn these ports from the node metadata exchanged on membership. Existing configurations keep working.

### Documentation

- The [actor lifecycle page](https://docs.goakt.dev/actor/lifecycle) now states that `PostStart` is delivered before any other message, and describes `PoisonPill` as the priority message it is: it is handled ahead of the user messages still queued, which are discarded, not after them. For a shutdown that first handles everything sent before it, the page shows a stop message of your own handled with `ctx.Shutdown()`.
- The [actor lifecycle page](https://docs.goakt.dev/actor/lifecycle) now states that the name of a stopped actor is free as soon as the stop returns, in cluster mode too when the name is spawned again on the same node.
- The [service discovery page](https://docs.goakt.dev/clustering/service-discovery) now covers every built-in provider, with its configuration and a complete example.

- `docs/advanced/streams.mdx` no longer lists overflow strategies, a `MicroBatch` field and metric methods that do not exist, and documents the stream behaviour above.
- The remoting, distributed-data, reliable-delivery, supervision, death-watch and passivation pages describe the behaviour above.
- The design notes in `design/` are replaced by *GoAkt from the Inside*, the maintainers' book in `book/`: an architecture overview (`book/architecture.md`), chapters for the dispatcher pool, reentrancy, the remoting transport, reliable delivery, distributed data and reactive streams, and the v3 to v4 migration guide (`book/migration/v3-to-v4.md`).
