# Unreleased

## Highlights

- **Grain scheduling and one-way tell.** A grain can now receive a message once after a delay, at an interval or on a cron expression, and `TellGrain` can return as soon as the message is enqueued.
- **Sturdier crash recovery.** A node that dies during a rebalance is no longer missed, a node that comes back is no longer relocated, and a crashed node no longer keeps the names of its non-relocatable actors and grains.
- **Unambiguous actor names.** Concurrent spawns of one name leave one actor, addresses carry the full ancestor path, and same-named children under different parents no longer share a registry record.
- **Simpler networking and discovery.** A wildcard bind address listens on every interface, mDNS discovery is rebuilt on `hashicorp/mdns`, and every built-in discovery provider is documented.
- **Fewer dependencies.** Four modules are gone, and the library's retries now share one exponential backoff with jitter.

## Upgrade Notes

- **Clusters on mDNS discovery need a full restart.** The mDNS provider was rebuilt, and nodes on the old and the new provider do not discover each other, so stop the whole cluster and start it again rather than rolling the upgrade.
- **Clusters on any other discovery provider can be upgraded one node at a time.** The mDNS rebuild is the only change that rules out a rolling upgrade. While nodes on the previous version and on this one run side by side, expect the following. Each item clears once every node is upgraded.
  - **Deeply nested actors.** A node on the previous version cannot parse the address of an actor nested two or more levels deep, such as a grandchild, and rejects it with `address format is invalid`. Top-level actors and direct children are unaffected.
  - **Child lookups from another node.** An upgraded node registers a child actor under its qualified name (`parent/child`); a node on the previous version registers it under its bare name (`child`). A lookup from another node succeeds only with the key the child's host used. Top-level actors are unaffected.
  - **Concurrent spawns of one name.** A node on the previous version still publishes actors the old way, so two spawns of the same name at the same time may still both succeed when one of them runs on such a node. The one-actor-per-name guarantee holds once every node is upgraded.
  - **One-way `TellGrain`.** When the grain lives on a node running the previous version, that node ignores the one-way option and acknowledges after processing, so the call waits as it did before. Delivery itself is unaffected.

## Changes

### Features

- **Message scheduling for grains** ([#1372](https://github.com/Tochemey/goakt/issues/1372)). `ScheduleGrainOnce`, `ScheduleGrain` and `ScheduleGrainWithCron` deliver a message to a grain once after a delay, at a fixed interval or on a cron expression. Delivery is a one-way `TellGrain` that reaches the grain wherever it lives and reactivates it if it has passivated. Grain schedules share references, `CancelSchedule`, `PauseSchedule`, `ResumeSchedule`, metrics and cluster rules with actor schedules, and `ListSchedules` reports them through the new `ScheduleInfo.Grain` field. They outlive the grain's activation and, like actor schedules, are not persisted.
- **One-way tell for grains** ([#1370](https://github.com/Tochemey/goakt/issues/1370)). `TellGrain` on the actor system and on `GrainContext` accepts `actor.WithOneWay()`, and `client.TellGrain` accepts `client.WithOneWay()`. The call returns once the message is enqueued; errors before the enqueue are still returned, and a handler failure or panic is recorded as a deadletter. Without the option the call waits for the acknowledgement as before.
- **mDNS discovery accepts a logger** ([#1368](https://github.com/Tochemey/goakt/issues/1368)). `mdns.NewDiscovery` takes `mdns.WithLogger`, which routes the provider's and the library's output to your logger. The default discards it.
- **Actor qualified name**. The new `actor.QualifiedName` function builds the name that identifies an actor within its actor system: the names of its ancestors from the root down, then its own, joined by `/`. `actor.QualifiedName("orders", "worker")` returns `orders/worker`, and a single name is returned unchanged. `ActorOf`, `ActorExists`, `Kill` and `ReSpawn` resolve that name, locally and in a cluster. Every name must pass the checks `Spawn` applies: the first one that fails them is reported with `ErrInvalidActorName`, or with `ErrReservedName` when it is reserved for system actors.
- **Qualified name of a running actor**. The new `QualifiedName` method on `Path` returns the same name for a running actor: `pid.Path().QualifiedName()` is `orders/worker` for a child and the actor's own name for a top-level actor.

### Fixes

- **A node that is shutting down no longer takes new grains** ([#1396](https://github.com/Tochemey/goakt/issues/1396)). A remote activation sent to a node that is shutting down is refused with `ErrSystemShuttingDown`, and a node whose owner answers that it is shutting down, or that its remoting is off, releases the owner's registry record and activates the grain on a live node. Before, a stopping node accepted activations until the end of its shutdown, the records of those grains outlived it, and a node that still held a connection to it kept being answered `remoting is not enabled`, which did not count as a departed owner, so the grain stayed unreachable until the connection was refused.
- **A crashed node no longer keeps the names of its non-relocatable actors** ([#1386](https://github.com/Tochemey/goakt/issues/1386)). When a node died without a shutdown, the registry records of its non-relocatable actors and grains survived it. Both are now released. Neither kind is recreated by the framework; only names and entries are freed.
  - **Actors.** An actor spawned with `WithRelocationDisabled` kept owning its name: `ActorOf` and `ActorExists` answered with the dead node, and a fresh spawn of the name failed with `ErrActorAlreadyExists`. The leader now releases those claims once crash recovery confirms the node is gone, and a spawn that meets such a claim writes its own record over it after checking that its holder is no longer a cluster member. Both are fenced by the actor incarnation, so a name a newer actor already claimed is never removed or written over.
  - **Grains.** A grain activated with `WithGrainDisableRelocation` had the same leak: its directory entry outlived the node until the next `GrainIdentity` call, and `TellGrain` and `AskGrain` failed against the dead node in the meantime. Crash recovery now releases that entry too, so the next message re-creates the grain on a live node.
  - **Lookups.** `ActorOf`, `ActorExists` and `Kill` apply the same membership check, so a non-relocatable actor on a departed node reports not found even before the leader releases its claim. Relocatable actors and singletons, which come back under the same name, stay resolvable while they are recreated.
  - **Convergence window.** While the cluster converges after the node loss, a registry read that runs out of its internal timeout while the caller's context is still alive now returns the new `ErrClusterRegistryTimeout`, which still matches `context.DeadlineExceeded`, so callers can tell it from their own deadline. In that window the registry also refuses to delete a record while a copy of it lives on the departed node, so a spawn that had to delete the dead node's claim first failed with `ErrActorAlreadyExists` while `ActorOf` already reported the actor as not found ([#1391](https://github.com/Tochemey/goakt/issues/1391)). The spawn now writes its own record over the claim instead, and a publication refused because another incarnation owns the name no longer takes the name's lock to find that out.
- **Crash recovery no longer misses a node that died during a rebalance** ([#1387](https://github.com/Tochemey/goakt/pull/1387)). The cluster engine defers `NodeLeft` until the routing table has converged on the departure. A rebalance epoch that started before a crash and completed after it still listed the dead node with a newer generation, so the engine took the departure for a restart, dropped it for good and never announced `NodeLeft`: nothing on that node was recovered, and the leader logged only `dropping stale departure`. The engine now checks the current membership before dropping such a departure. A member's is a stale copy and is dropped as before; a non-member's stays pending until the next convergence without it, or the bounded wait, announces it.
- **Concurrent spawns of one name leave one actor** ([#1377](https://github.com/Tochemey/goakt/issues/1377)). Two nodes spawning the same name at once could both succeed and keep two live actors, and stopping either deleted the other's registry record. The first spawn now wins, the others fail with `ErrActorAlreadyExists` and leave nothing behind, and a registry record is updated or removed only by the actor that owns it, so a stopped or rolled-back copy never touches the live one. A spawn costs what it did before, and concurrent spawns of different names on one node complete about three times faster because publishing no longer holds the node's registry write lock; the new `BenchmarkClusterSpawn` measures both.
- **Actor addresses carry the full path** ([#1379](https://github.com/Tochemey/goakt/issues/1379)). An address now renders every ancestor of the actor, `goakt://system@host:port/grand/parent/name`, and parses it back, as documented. Only the immediate parent used to be written, so two actors nested under same-named parents shared one address and the second `SpawnChild` returned the first actor. Top-level actors and direct children keep the addresses they had. Large-message destination patterns see the full path, one `*` per segment.
- **Same-named children no longer overwrite or delete each other's records** ([#1380](https://github.com/Tochemey/goakt/issues/1380)). Two children with the same name under different parents used to share one registry record and one local name entry: the second spawn replaced the first, and stopping either deleted the other's record while it was still running. Registry records are now keyed by the qualified actor name, the ancestor names and its own joined by `/` (`p1/kid`), and the local name index keeps every named actor. Top-level lookups are unchanged. A child is found by its qualified name from any node (`ActorOf(ctx, "p1/kid")`) and by its bare name on its own node, which returns the most recently spawned child of that name; a bare-name lookup from another node returns not found. Spawning a top-level actor with the name of a running child now creates the actor, and `Reinstate` of a child finds that child.
- **Crash recovery no longer relocates the actors and grains of a node that came back** ([#1383](https://github.com/Tochemey/goakt/issues/1383)). When a node left without a shutdown snapshot, the leader waited for the partition repair to go quiet and relocated whatever the registry still listed for it, without checking that the node was still gone. A transient departure, such as a failed and retried bootstrap, had the node rejoin at the same address, keep its actors and grains, and see them relocated anyway, leaving two live instances of each. The leader now checks the membership after the wait and again before dispatching the relocation set, and skips the recovery with a warning when the node is a member again. A node that really crashed is recovered as before.
- **etcd discovery validates `Timeout`.** A zero `Timeout` is rejected at validation instead of failing every request at runtime, in line with `DialTimeout` and `TTL`.
- **A wildcard bind address listens on every interface** ([#1374](https://github.com/Tochemey/goakt/issues/1374)). `remote.NewConfig("0.0.0.0", port)` used to bind the remoting server to one guessed private IP, so connections through loopback or any other interface were refused, and start failed on a host with no private or public address. The server now listens on the wildcard as configured, `::` serves IPv4 and IPv6 peers, and a host with no other address advertises loopback. What peers are told is unchanged: `ActorSystem.Host()`, actor addresses and cluster membership still advertise the first private IP, and cluster gossip and the registry still bind it. Bind a concrete IP to listen on one interface only.

### Behavior Changes

- **mDNS discovery rebuilt on `hashicorp/mdns`** ([#1368](https://github.com/Tochemey/goakt/issues/1368)). Each node registers its own instance name and carries the cluster name in its TXT record; configuration is unchanged. Peers learn one IPv4 address and, with `IPv6` set to true, one IPv6 address per node; IPv6-only networks are not supported. See the upgrade notes above.
- **Sorted results where the order used to be unspecified.** Kubernetes, mDNS and DNS-SD peer addresses (deduplicated), `Peer.Roles` and `ActorSystem.Grains` now come back sorted.
- **Retry delays follow a new curve.** Every retry that ran on `flowchartsman/retry` now runs on `cenkalti/backoff`: spawn, initialization, grain activation, supervised child restart, routee restart, relocation, reliable delivery, shutdown hooks, remote stream endpoint resolution and NATS discovery. Delays double with up to fifty percent jitter within the same bounds; where a retry's bounds are equal the delay stays fixed and only gains jitter. Attempt counts, defaults and returned errors are unchanged.

### Deprecations

- **Kubernetes discovery: `RemotingPortName` and `PeersPortName`.** Both fields are deprecated and ignored; peers learn these ports from the node metadata exchanged on membership. Existing configurations keep working.

### Documentation

- The [service discovery page](https://docs.goakt.dev/clustering/service-discovery) now covers every built-in provider, with its configuration and a complete example.
