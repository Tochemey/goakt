# Unreleased

## ✨ Features

- **Runtime metrics for unhandled messages, actor lifecycle edges, and dead-letter message types** ([#1323](https://github.com/Tochemey/goakt/issues/1323)). Four instruments are added and one is refined:
  - `actor.unhandled.count` (Int64ObservableCounter, per actor) reports how many messages the actor rejected through `ReceiveContext.Unhandled`. It resets on restart like the other per-actor counters and is also exposed on the `pid.Metric(ctx)` snapshot as `UnhandledCount`, on the remote metric wire message, and on `ActorMetric` in the `internal/metric` package.
  - `actor.spawned.count`, `actor.stopped.count` and `actor.passivated.count` (Int64ObservableCounter) report actor lifecycle edges per actor kind, carrying the `actor.system` and `actor.kind` attributes. They live on the actor system because each edge adds or removes the actor from the tree, so no PID survives to carry them. System actors are excluded. `actor.stopped.count` counts terminal stops only: the teardown a restart performs is reported by `actor.restart.count` and a passivation by `actor.passivated.count`, so no event is counted twice.
  - `actor.deadletters.count` now carries a `message.type` attribute naming the type of the dropped message, and is reported once per message type the actor dropped, so the number says which messages an actor is losing. An actor that has dropped nothing still reports a single zero without the attribute. Sum the series to recover an actor's total.

  Capture is a plain atomic increment at the spawn, stop, passivation, `Unhandled` and dead-letter sites; the message path is untouched and no OpenTelemetry call runs on it.

  `WithMetrics` now accepts options, and `WithMetrics(WithLowCardinalityMetrics())` reports the per-actor instruments once per actor kind instead of once per actor, carrying only the `actor.system` and `actor.kind` attributes. The scrape aggregates the live actors of each kind: the counters are summed, `actor.uptime` is reduced to the age of the kind's oldest live actor, `actor.last.received.duration` to the time since the kind last processed a message, and `actor.deadletters.count` is summed per kind and message type. The series count then depends on how many actor kinds a system declares rather than on how many actors it runs, at the cost of the `actor.name` and `actor.address` attributes, which the mode drops. The default is unchanged: without the option every instrument is still reported once per actor with the same attributes as before. The aggregation runs inside the existing scrape callback, so the message path is again untouched.

## 🔧 Fixes

- **Runtime metric instruments report the correct type and the deadletter scrape no longer floods a single mailbox** ([#1322](https://github.com/Tochemey/goakt/issues/1322)). The instruments that report an absolute current value that can fall (`actorsystem.actors.count`, `actorsystem.peers.count`, `actorsystem.uptime`, `actor.children.count`, `actor.stash.size`, `actor.uptime`, `actor.last.received.duration`) were registered as monotonic observable counters, so exporters that derive rates or deltas mishandled every decrease; they are now observable gauges. The per-actor metrics callback asked the deadletter actor for its count once per running actor per scrape, flooding a single mailbox at large populations; it now asks once per scrape for a snapshot of all per-address counts. `crdt.replicator.crossdc.replication.lag` is now reported in milliseconds instead of nanoseconds to match the other duration instruments.
