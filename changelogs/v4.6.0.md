# v4.6.0 - 2026-10-05

## Highlights

- **Grain scheduling and one-way tell.** A grain can now receive a message once after a delay, at an interval or on a cron expression, and `TellGrain` can return as soon as the message is enqueued.
- **Sturdier crash recovery.** A node that dies during a rebalance is no longer missed, a node that comes back is no longer relocated, and a crashed node no longer keeps the names of its non-relocatable actors and grains.
- **Unambiguous actor names.** Concurrent spawns of one name leave one actor, addresses carry the full ancestor path, and same-named children under different parents no longer share a registry record.
- **Simpler networking and discovery.** A wildcard bind address listens on every interface, mDNS discovery is rebuilt on `hashicorp/mdns`, and every built-in discovery provider is documented.
- **Fewer dependencies.** Four modules are replaced by two, and the library's retries now share one exponential backoff with jitter.
- **Distributed data that converges.** An `ORSet` peer no longer loses elements, anti-entropy repairs diverging values and missed deletions, a node back after the tombstone TTL no longer revives deleted keys, watchers receive `crdt.Deleted`, and cross-datacenter replication keeps a batch until each datacenter accepts it.
- **Asks that stop when nobody waits.** Actors and grains skip an ask whose sender stopped waiting, and the handler's context ends with the ask.
- **Graceful shutdown.** `Stop` no longer fails when peers leave at the same time, and a stopping node refuses new grains and grain requests it can no longer honor.
- **Predictable actor lifecycle.** `PostStart` is always the first message, a stopped actor frees its name before the stop returns, restarts keep names and records, and a failed restart stops the whole subtree.
- **Compression on the default protocol.** `remote.WithCompression` now compresses duplex connections, which every current node uses, and closing a compressed connection is safe.
- **Streams that respect demand and clean up.** Every stage pulls only what its downstream asked for, a failing input fails the stream, nothing a stream started outlives it, and fan-out graphs can run more than once.

## Upgrade Notes

- **Clusters on mDNS discovery need a full restart.** Nodes on the old and the new mDNS provider do not discover each other.
  - The mDNS provider was rebuilt, so stop the whole cluster and start it again rather than rolling the upgrade.
- **Clusters on any other discovery provider can be upgraded one node at a time.** The mDNS rebuild is the only change that rules out a rolling upgrade.
  - While nodes on the previous version and on this one run side by side, expect the items below.
  - Each item clears once every node is upgraded.
- **Mixed versions: deeply nested actors.** A previous-version node rejects the address of an actor nested two or more levels deep.
  - The address of a grandchild, for example, is rejected with `address format is invalid`.
  - Top-level actors and direct children are unaffected.
- **Mixed versions: child lookups from another node.** A lookup succeeds only with the key the child's host used.
  - An upgraded node registers a child actor under its qualified name (`parent/child`).
  - A node on the previous version registers it under its bare name (`child`).
  - Top-level actors are unaffected.
- **Mixed versions: concurrent spawns of one name.** Two spawns of the same name at the same time may still both succeed.
  - This happens when one of them runs on a node on the previous version, which still publishes actors the old way.
  - The one-actor-per-name guarantee holds once every node is upgraded.
- **Mixed versions: grains on a stopping node.** A previous-version node gets an error instead of activating the grain elsewhere.
  - A node on the previous version does not recognize the refusal of a stopping upgraded node.
  - Its `GrainIdentity` or `GrainOf` call for a grain placed there returns an error.
  - Retrying succeeds once the stopping node has left.
- **Mixed versions: one-way `TellGrain`.** A previous-version grain host ignores the one-way option.
  - That node acknowledges after processing, so the call waits as it did before.
  - Delivery itself is unaffected.
- **Mixed versions: compression.** An upgraded node compresses a duplex connection when both sides name the same codec.
  - A node on the previous version that has `WithCompression` set starts compressing when it dials an upgraded node.
  - It keeps the previous version's unsafe close of a compressed connection until it is upgraded too.
- **Mixed versions: distributed data anti-entropy.** Values that differ under equal versions and missed deletions are repaired only between upgraded nodes.
  - The content hash and the deletions carried by anti-entropy are new optional fields.
  - Between an upgraded node and a node on the previous version, anti-entropy follows the version rule it used before.
- **Mixed versions: distributed data after a long absence.** A previous-version node never resolves the stale keys of a node back after the tombstone TTL.
  - The time from which a node knows every deletion is a new optional field of the anti-entropy digest, and a node on the previous version sends none.
  - The stale keys are kept once every peer has been heard from.
  - A snapshot written by the previous version has no last contact, so a node restored from it is treated as having no gap, as before.
- **Mixed versions: refusals of a stopping grain owner.** A call that meets a previous-version stopping owner returns `ErrSystemShuttingDown` and keeps its record, as before.
  - An upgraded node marks on the wire a grain message it refused because it is stopping.
  - `TellGrain` and `AskGrain` send such a message again on a live node only when the mark is present.
  - A node on the previous version does not mark its refusals and ignores the mark.
- **Mixed versions: supervisor backoff on another node.** A previous-version node supervises without backoff, as before.
  - The backoff of a supervisor travels with an actor spawned on another node or relocated there.
  - A node on the previous version ignores it.

## Features

- **Dispatcher pool size** ([#1400](https://github.com/Tochemey/goakt/issues/1400)). `WithDispatcherPoolSize` sets the size of the worker pool that runs actor and grain turns.
  - The default is `max(GOMAXPROCS, 2)`.
  - A handler that blocks in its turn, on a database call or a synchronous request, holds its worker for the whole wait.
  - With the default, no more than GOMAXPROCS actors and grains make progress at once.
  - A larger pool lets that many blocking handlers wait at the same time.
  - One-at-a-time execution per actor and per grain is unchanged.
  - The pool is shared by every actor and grain, so a pool much larger than `GOMAXPROCS` slows dispatch for handlers that do not block.
- **Cluster store directory** ([#1403](https://github.com/Tochemey/goakt/issues/1403)). `ClusterConfig.WithStoreDir` sets the directory a node keeps its cluster store in.
  - The cluster store is the BoltDB file that persists the node's peer state.
  - The default stays `~/.goakt/cluster`.
  - The default fails on a pod with a read-only root filesystem or in a sandbox without a home directory; point it at a writable volume there.
- **`AskGrain` and `TellGrain` release a stale grain owner record** ([#1435](https://github.com/Tochemey/goakt/issues/1435)). They now release the record of an owner that was stopping or had left the cluster.
  - Before, only `GrainOf` and `GrainIdentity` released such a record, so a bare send failed until something else released it.
  - When the owner refused the message because it is stopping, the message did not run, and the call sends it again to the grain activated on the calling node.
  - The same happens when the owner left the cluster and the calling node could not even connect to it, since the request never left.
  - The resend uses the recorded configuration, within what is left of the call's timeout.
  - When the owner left with the message in flight, the call returns the transport error without sending again, because the message may have run.
  - The next call reaches the grain on a live node.
  - A call sends a message again at most once.
  - An `ErrSystemShuttingDown` returned by a grain handler is not a refusal and keeps the record.
- **Grain registry writes are retried** ([#1435](https://github.com/Tochemey/goakt/issues/1435)). The writes of a grain activation and of a release are now tried again a few times.
  - These writes are the claim, the publication of the record and the release of an owner's entry.
  - The registry can fail a write it still routes to a node that is leaving.
  - Before, a few hundred calls per million failed with `context canceled` during a rolling restart.
- **Watchers hear of deletions** ([#1436](https://github.com/Tochemey/goakt/issues/1436)). An actor subscribed with `crdt.Subscribe` now receives `crdt.Deleted` carrying the key when its node removes its copy.
  - This applies whether the key was deleted on that node, on a peer or in another datacenter.
  - A node that does not hold the key sends nothing, and each node announces a deletion once.
  - The watcher stays subscribed and receives `Changed` again if the key is created after its tombstone has expired.
- **Grain options per kind** ([#1402](https://github.com/Tochemey/goakt/issues/1402)). `WithGrainDefaultOptions[*MyGrain](opts...)` declares the options every grain of that kind is configured with.
  - They apply under the options of a `GrainOf` call and under the options a registry record carries.
  - They apply alone for a bare send that creates the grain.
  - Before, a bare `AskGrain` or `TellGrain` that found the grain passivated reactivated it with the package defaults.
  - Before, a grain activated on another node got the default idle timeout.
  - The safe pattern used to be `GrainOf` with the full option list before every send.
- **Message scheduling for grains** ([#1372](https://github.com/Tochemey/goakt/issues/1372)). `ScheduleGrainOnce`, `ScheduleGrain` and `ScheduleGrainWithCron` deliver a message to a grain once, at an interval or on a cron expression.
  - Delivery is a one-way `TellGrain` that reaches the grain wherever it lives and reactivates it if it has passivated.
  - Grain schedules share references, `CancelSchedule`, `PauseSchedule`, `ResumeSchedule`, metrics and cluster rules with actor schedules.
  - `ListSchedules` reports them through the new `ScheduleInfo.Grain` field.
  - They outlive the grain's activation and, like actor schedules, are not persisted.
- **One-way tell for grains** ([#1370](https://github.com/Tochemey/goakt/issues/1370)). `TellGrain` can return as soon as the message is enqueued.
  - `TellGrain` on the actor system and on `GrainContext` accepts `actor.WithOneWay()`.
  - `client.TellGrain` accepts `client.WithOneWay()`.
  - Errors before the enqueue are still returned, and a handler failure or panic is recorded as a deadletter.
  - Without the option the call waits for the acknowledgement as before.
- **mDNS discovery accepts a logger** ([#1368](https://github.com/Tochemey/goakt/issues/1368)). `mdns.NewDiscovery` takes `mdns.WithLogger`.
  - It routes the provider's and the library's output to your logger.
  - The default discards it.
- **Actor qualified name** ([#1390](https://github.com/Tochemey/goakt/pull/1390)). `actor.QualifiedName` builds the name that identifies an actor within its actor system.
  - The name is the names of its ancestors from the root down, then its own, joined by `/`.
  - `actor.QualifiedName("orders", "worker")` returns `orders/worker`, and a single name is returned unchanged.
  - `ActorOf`, `ActorExists`, `Kill` and `ReSpawn` resolve that name, locally and in a cluster.
  - Every name must pass the checks `Spawn` applies.
  - The first name that fails them is reported with `ErrInvalidActorName`, or with `ErrReservedName` when it is reserved for system actors.
- **Qualified name of a running actor** ([#1390](https://github.com/Tochemey/goakt/pull/1390)). `Path.QualifiedName()` returns the same name for a running actor.
  - `pid.Path().QualifiedName()` is `orders/worker` for a child and the actor's own name for a top-level actor.
- **Dial timeout for remoting** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). `remote.WithDialTimeout` sets how long a node waits to open a TCP connection to a peer.
  - The default is five seconds.
  - A dial to an address that drops packets, such as the IP of a departed Kubernetes pod, fails on its own timeout instead of on the caller's deadline.
  - This lets the sender recognize a departed grain owner and release its record.
- **Content hash for replicated data** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). Every built-in CRDT type implements the new optional `crdt.StateHasher` interface.
  - `StateHash` returns a hash that is equal for equal states, whatever the order of the operations that produced them.

## Behavior Changes

- **Substream buffers default to `BackpressureSource`** ([#1434](https://github.com/Tochemey/goakt/issues/1434)). A substream slower than its source now holds the source back instead of dropping new elements.
  - Holding the source back also holds back every other substream.
  - Pass `WithSubstreamBuffer(n, stream.DropTail)` to keep dropping.
  - A slow downstream holds the source back under every strategy, so `DropTail` and `FailSource` no longer drop or fail because of it.
  - They apply only while the downstream asks for elements.
  - A key that carries most of the elements can still reach the cap in bursts while the downstream keeps up.
  - In that case `DropTail` drops some of its elements and `FailSource` can fail, far less often than before.
- **The context of an ask ends with the ask** ([#1407](https://github.com/Tochemey/goakt/issues/1407)). Handler contexts now end at the ask deadline and when the handler returns.
  - For a message sent with `AskGrain`, `GrainContext.Context()` ends at the ask deadline and when `OnReceive` returns.
  - After `DeferResponse` it ends at the deadline only.
  - For a message sent to an actor with `Ask`, `ReceiveContext.Context()` ends at the ask deadline and when `Receive` returns.
  - A handler that hands this context to work that outlives the ask, a goroutine or a `PipeTo` task, must detach it with `context.WithoutCancel`.
  - The context of a tell is unchanged.
- **`Stop` no longer reports a failed registry removal** ([#1415](https://github.com/Tochemey/goakt/issues/1415)). The error is logged as a warning instead of being returned.
  - This covers removing the stopping node's actor and grain records from the cluster registry.
  - A grain that is deactivated while its node keeps running still reports a failed removal.
  - Errors from leaving the cluster and from closing the cluster store are still returned.
  - A failed handover of the node's state to a peer that is not leaving itself is still returned.
- **`PostStart` no longer goes through the mailbox** ([#1422](https://github.com/Tochemey/goakt/issues/1422)). It is delivered from its own slot.
  - A full bounded mailbox can no longer refuse it.
  - A custom mailbox never sees it.
  - It no longer counts towards the `actor.mailbox.size` metric.
- **`PostStart` after a restart can run before the children are back** ([#1422](https://github.com/Tochemey/goakt/issues/1422)). The new incarnation's `PostStart` runs as soon as any message reaches the actor.
  - Before, it was delivered only once the children were back.
  - A `PostStart` handler that uses its children should look them up rather than assume they are running.
- **A failed restart stops the whole subtree** ([#1423](https://github.com/Tochemey/goakt/issues/1423)). This applies when `Restart` or `ReSpawn` fails.
  - A restart fails when `PreStart` returns an error or a child cannot be restarted.
  - Every actor of the subtree is stopped, its watchers receive `Terminated`, and its name and registry record are released.
  - Before, children restarted before the failure kept running under a parent that was not.
  - Before, the failed actor could keep its name.
- **A stop directive no longer reports a dead sibling as suspended** ([#1423](https://github.com/Tochemey/goakt/issues/1423)). The sibling is simply stopped and its name is free.
  - With a one-for-all stop directive, a sibling whose `PostStop` failed was marked suspended.
  - An `ActorSuspended` event was published for it, although it was dead.
- **CRDT watchers receive `crdt.Deleted`** ([#1436](https://github.com/Tochemey/goakt/issues/1436)). A subscribed actor that does not handle the new message treats it like any other unhandled message.
  - It handles it as it would a `Changed` it does not handle.
- **Watchers are told when `PostStop` fails** ([#1423](https://github.com/Tochemey/goakt/issues/1423)). They now receive `Terminated`.
  - This covers an actor whose `PostStop` returned an error or whose children failed to stop.
  - Before, such an actor was marked as stopped without sending `Terminated` to its watchers.
  - `Shutdown` and `Kill` still return the error.
- **A shutting down node refuses grain requests it can no longer honor** ([#1396](https://github.com/Tochemey/goakt/issues/1396), [#1397](https://github.com/Tochemey/goakt/issues/1397)). Such requests are refused with `ErrSystemShuttingDown`.
  - From the moment a node starts shutting down, it no longer activates grains.
  - Messages still queued behind a grain's deactivation are no longer handed to the deactivated grain.
  - Before, such calls appeared to succeed, but some were handled by a grain about to be dropped or already past `OnDeactivate`, so their effects could be lost.
  - During a rolling restart, callers may see a few `ErrSystemShuttingDown` errors per restarting grain.
  - The message was not processed, so it is safe to send it again; in a cluster the retry reaches the grain on a live node.
- **mDNS discovery rebuilt on `hashicorp/mdns`** ([#1368](https://github.com/Tochemey/goakt/issues/1368)). Configuration is unchanged.
  - Each node registers its own instance name and carries the cluster name in its TXT record.
  - Peers learn one IPv4 address and, with `IPv6` set to true, one IPv6 address per node.
  - IPv6-only networks are not supported.
  - See the upgrade notes above.
- **Sorted results where the order used to be unspecified** ([#1367](https://github.com/Tochemey/goakt/pull/1367)). Several results now come back sorted.
  - Kubernetes, mDNS and DNS-SD peer addresses come back sorted and deduplicated.
  - `Peer.Roles` and `ActorSystem.Grains` come back sorted.
- **Retry delays follow a new curve** ([#1367](https://github.com/Tochemey/goakt/pull/1367)). Every retry that ran on `flowchartsman/retry` now runs on `cenkalti/backoff`.
  - This covers spawn, initialization, grain activation, supervised child restart, routee restart and relocation.
  - It also covers reliable delivery, shutdown hooks, remote stream endpoint resolution and NATS discovery.
  - Delays double with up to fifty percent jitter within the same bounds.
  - Where a retry's bounds are equal, the delay stays fixed and only gains jitter.
  - Attempt counts, defaults and returned errors are unchanged.
- **Supervision matches a panic's error** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). A panic with an error follows the rule for that error's type, then the `PanicError` rule, then the any-error rule.
  - Before, only the `PanicError` rule applied.
  - `panic(nil)` follows the `PanicNilError` rule, which restarts by default.
- **Restarts run `PostStop` and keep state** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). A supervised restart and `Restart` both run `PostStop` before `PreStart`.
  - Both keep watches, dependencies and counters.
  - Neither tells watchers `Terminated`.
- **Round robin rotates in spawn order** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). Before, the order was unspecified.
- **A retried stream stage makes 1 + `MaxAttempts` calls** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). This holds whatever the order of `WithErrorStrategy` and `WithRetryConfig`.
  - Before, the retry configuration was ignored when set after the strategy.
- **`FromChannel` reads only against demand** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). A producer writing to the channel now blocks until the stream asks for more.
  - A closed channel is noticed when the stream next asks.
- **A failing fan-in input fails the stream** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). What was buffered is discarded.
  - Before, the failure was treated as that input completing.
- **`Stop` counts a peer that closes the connection as leaving** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). It is treated like a peer that refuses the connection.
  - This applies during the state handover, when a peer closes the connection under the request.
  - `Stop` no longer fails because a peer was stopping at the same moment.

## Fixes

- **A `NodeLeft` handled after `Stop` no longer panics** ([#1444](https://github.com/Tochemey/goakt/issues/1444), [#1445](https://github.com/Tochemey/goakt/pull/1445)). The handler now ignores a departure once `Stop` has cleared the cluster store.
  - A node handles a `NodeLeft` on its cluster events goroutine, and `Stop` does not wait for that handler.
  - When the node stopped while handling one, the handler read the cleared cluster store and panicked with a nil pointer dereference.
  - The panic was on a goroutine GoAkt starts, so it ended the process.
  - A slow logger or the scheduler opens the window, for example when a peer leaves during a rolling restart.
  - A peer state request still in flight when `Stop` resets the system now fails with `ErrClusterDisabled` instead of panicking.
  - See `playground/issue-1444`.
- **Distributed data no longer sends to nodes without a Replicator** ([#1443](https://github.com/Tochemey/goakt/pull/1443)). Such nodes are now skipped.
  - Anti-entropy, coordinated `WriteTo` and `ReadFrom` calls, the cross-datacenter flush and cross-datacenter anti-entropy used a peer's Replicator lookup unchecked.
  - A node that runs none, because `crdt.WithRole` leaves it out or because it is starting or stopping, answers that lookup with no address.
  - The round was then lost with a `remote tell to :0 failed` warning.
  - The cross-datacenter flush counted the batch as accepted by a datacenter it never reached.
  - Anti-entropy and coordination now pick only peers with the CRDT role.
  - The flush moves on to another endpoint of the datacenter and keeps the batch until one of them takes it.
- **Grain calls ride out a registry read timeout** ([#1443](https://github.com/Tochemey/goakt/pull/1443)). The read is now tried again within the caller's context, as registry writes already were.
  - While the cluster converges after a node leaves, a grain registry read routed to that node can run out of its timeout.
  - `TellGrain`, `AskGrain`, `GrainOf` and `GrainIdentity` then failed with `ErrClusterRegistryTimeout`.
  - The read is tried at most three times, 100 ms to 500 ms apart.
  - Any other error is still returned at once.
- **`MergeSubstreams` holds its source back under a slow downstream** ([#1434](https://github.com/Tochemey/goakt/issues/1434)). Its buffering is now bounded.
  - The splitter collected the output of every substream in one buffer with no limit and pulled the source at full speed.
  - A slow downstream made it hold everything the source produced that it did not drop.
  - A million elements through four `GroupBy` keys into a blocked sink pulled the whole source, kept more than half a million and dropped the rest.
  - Each substream now sends at most one demand window ahead of what the downstream has taken.
  - The splitter takes no element from the source while its merged buffer holds a window.
  - The same stream now pulls under a thousand elements and drops none.
  - `BackpressureSource` on `WithSubstreamBuffer` now holds the source back when a substream is at its in-flight cap, where before it dropped like `DropTail`.
  - See `playground/issue-1434`.
- **A node back after the tombstone TTL no longer brings deleted keys back** ([#1437](https://github.com/Tochemey/goakt/issues/1437)). Stale keys are now resolved against a peer that saw the whole gap.
  - A tombstone is pruned once it is older than `crdt.WithTombstoneTTL`, 24 hours by default.
  - A node away for longer that still held a deleted key brought it back, because no node retained the tombstone.
  - This happened after a restore from the CRDT snapshot or when the node kept running through a partition.
  - Each Replicator now records the last time it heard from a peer and saves it with its snapshot.
  - After a gap longer than the TTL, keys held before the gap and not updated since are stale and are not sent to peers.
  - A peer present for the whole gap keeps a stale key it holds and removes one it does not hold.
  - When no current peer was there for the whole gap, as after a full cluster restart, the stale keys are kept once every peer has been heard from.
  - Two groups of nodes that run apart for longer than the TTL still bring back each other's deleted keys when they merge.
  - See `playground/issue-1437`.
- **An actor no longer handles asks whose sender stopped waiting** ([#1430](https://github.com/Tochemey/goakt/issues/1430)). The actor counterpart of [#1407](https://github.com/Tochemey/goakt/issues/1407).
  - The timeout of `Ask` was a timer on the sender's side only.
  - An ask that waited in the mailbox or in the stash past its timeout was still handed to `Receive`.
  - The actor now skips an ask it dequeues after its sender stopped waiting.
  - That moment is the ask timeout, or the deadline of the sender's context when that comes first.
  - `ReceiveContext.Context()` ends at that moment.
  - Before, the context carried a deadline only when the sender's own context had one or the ask came from another node.
  - An ask already in `Receive` when its sender gives up still runs to the end.
  - Tells are unchanged.
  - See `playground/issue-1430`.
- **A timed out `Ask` to a remote actor returns `ErrRequestTimeout`** ([#1430](https://github.com/Tochemey/goakt/issues/1430)). The error now carries `ErrRequestTimeout` as well as the transport error.
  - `Ask` and `BatchAsk` against a remote actor returned only `context deadline exceeded` or an i/o timeout.
  - `errors.Is(err, ErrRequestTimeout)` was false, although it is true for a local actor and for a grain.
- **A grain no longer handles asks whose sender stopped waiting** ([#1407](https://github.com/Tochemey/goakt/issues/1407)). The grain skips an ask it dequeues after its sender stopped waiting.
  - The timeout of `AskGrain` was a timer on the sender's side only.
  - An ask that waited in the mailbox past its timeout was still handed to `OnReceive`.
  - A slow grain spent its turns on answers nobody read, and a sender that retried had its work done twice.
  - The grain now knows when the sender stops waiting: the ask timeout, or the deadline of the sender's context when that comes first.
  - The same moment is the deadline of `GrainContext.Context()`, so database or HTTP calls given that context stop when nobody waits.
  - Before, the context carried a deadline only when the sender's own context had one, and never for a grain with reentrancy.
  - This holds for a grain on the calling node or on another one, with or without reentrancy.
  - An ask already in `OnReceive` when its sender gives up still runs to the end, so handlers whose callers retry must stay idempotent.
  - Tells are unchanged.
  - See `playground/issue-1407`.
- **`Stop` no longer fails when the listed peers are leaving too** ([#1415](https://github.com/Tochemey/goakt/issues/1415)). Leaving peers are recognized and skipped.
  - A stopping node hands its actors and grains to its peers before it leaves the cluster.
  - When nodes stop one after another, the last one can still list peers that stopped a moment ago.
  - Those answer `remoting is not enabled` or `cluster is not enabled` on an open connection, or refuse a new one.
  - `Stop` counted these as failures and returned `failed to replicate state to any peer`, although no node was left to take the state.
  - The handover still goes to the three oldest peers first; when all three are leaving, it moves on to the next oldest ones.
  - Only when every listed peer is leaving is the handover skipped with a warning, and `Stop` succeeds.
  - A peer that does not answer in time, or fails to store the state, still fails the handover, and `Stop` still reports it.
- **`Stop` no longer fails when nodes stop together** ([#1415](https://github.com/Tochemey/goakt/issues/1415)). Removing the node's registry records is now best effort.
  - A stopping node removes the records of its actors and grains from the cluster registry, which is spread over the nodes.
  - The removal fails when the node holding a record is gone or stopping at the same time.
  - `Stop` returned `context canceled`, `connection refused`, a registry timeout, or `grain deactivation failed` for every grain.
  - Stopping a whole three-node cluster at once failed `Stop` on about half of the nodes.
  - A record left behind names a departed node, which the cluster already handles as it must after a crash.
  - Lookups skip such records, and the next spawn, relocation or grain activation replaces them.
  - A failed removal is now logged as a warning and `Stop` succeeds.
  - See `playground/issue-1415`.
- **A failed cluster shutdown no longer leaves the node marked as clustered** ([#1415](https://github.com/Tochemey/goakt/issues/1415)). The cluster flag and the relocation bookkeeping are cleared whatever the steps return.
  - The error is reported as before.
- **Crash recovery no longer outlives a stopped node** ([#1413](https://github.com/Tochemey/goakt/issues/1413)). Recovery now recognizes a stopped system at every checkpoint and returns.
  - The leader recovers a crashed node on a goroutine that retries a failed attempt after a five second backoff.
  - It learned of a shutdown only from a flag that `Stop` clears again once it is done.
  - A recovery that slept through the shutdown, or polled past a fast one, carried on against the stopped cluster.
  - It logged its remaining attempts for up to twenty seconds after `Stop` had returned.
- **A node that crashes, rejoins and crashes again is recovered** ([#1413](https://github.com/Tochemey/goakt/issues/1413)). Recovery keeps the remoting port cache entry of a node that rejoined.
  - When a crashed node came back at the same address while recovery was still waiting, the recovery gave up, as it should.
  - It also dropped the node's remoting port from the leader's cache, where the rejoin had just refreshed it.
  - The next crash then failed every attempt with `no cached remoting port`, and its actors and grains were never recreated.
  - Before the entry is dropped for good, the membership is now read once more.
- **A remote reply is decoded with its own serializer** ([#1411](https://github.com/Tochemey/goakt/issues/1411)). Asks to another node no longer fail when the reply uses a different serializer than the request.
  - A target that answered a CBOR request with a proto message, or the other way round, failed the caller with a decoding error.
  - The same ask worked locally.
  - This affected `AskGrain`, `RemoteAsk` and `RemoteBatchAsk`.
  - The request's serializer still decodes the reply first, so asks that worked are unchanged.
  - When it cannot, every registered serializer is tried, as the receiving node does for requests.
- **Grain send failures keep their sentinels across nodes** ([#1409](https://github.com/Tochemey/goakt/issues/1409)). A remote grain send returns the same sentinel as a local one.
  - A full bounded mailbox returns `ErrMailboxFull`.
  - No answer in time returns `ErrRequestTimeout`.
  - A grain no longer alive returns `ErrDead`.
  - Before, these were untyped internal errors carrying the text.
  - The owning node now reports these outcomes at debug level instead of as error log lines.
- **An actor handles `PostStart` before any other message** ([#1422](https://github.com/Tochemey/goakt/issues/1422)). `PostStart` now waits in a slot that every turn checks before both queues.
  - `PostStart` travelled through the user mailbox while `Terminated` and other system messages took a priority queue.
  - A child that stopped before its parent's first turn delivered its `Terminated` first.
  - The user guardian, parent of every top-level actor, panicked on that `Terminated`, and the root guardian shut the whole actor system down.
  - A `Kill` or `ReSpawn` right after `Start` was enough to trigger it on a busy machine.
  - `PostStart` is now the first message of every incarnation, after a spawn and after a restart.
  - The check adds no measurable cost in the processing benchmarks.
- **A stopped actor frees its name before the stop returns** ([#1423](https://github.com/Tochemey/goakt/issues/1423)). The stopping actor leaves the local tree and the live actor count itself.
  - Before, the name stayed in the tree until the death watch handled `Terminated` in a later turn.
  - A `Spawn` of the same name in that window started an unmanaged actor and returned the stopped one with no error.
  - `ActorOf` and `ActorExists` still found the stopped actor, and a `SpawnChild` after `Stop` returned a child its parent did not list.
  - The death watch now only removes the cluster registry record.
  - An actor whose `PostStop` fails is released the same way and its watchers are told; before, its name stayed taken for good.
  - In cluster mode, a spawn on the same node writes over the record the stopped actor left, fenced by that actor's incarnation.
- **Spawning a name held by an actor that is not running no longer starts a second actor** ([#1423](https://github.com/Tochemey/goakt/issues/1423)). `Spawn`, `SpawnNamedFromFunc`, `SpawnSingleton` and `SpawnChild` now return `ErrActorAlreadyExists` and start nothing.
  - Before, they returned the existing actor only when it was running.
  - For a suspended, stopping or restarting holder, they started a new actor that could not register and kept running with nothing to stop it.
  - Reinstate, restart or stop the actor that holds the name, then spawn again.
- **A restart keeps its names and registry records** ([#1423](https://github.com/Tochemey/goakt/issues/1423)). The restarted actor and its children keep them for the whole restart, updated in place.
  - The teardown of a restart was reported to the death watch as a death.
  - The registry records were removed and written again, and the name was briefly free.
  - Another node could claim the name in between.
  - A removal handled late could delete the record of the actor that had just restarted.
- **Shutdown reaches a grain whose bounded mailbox is full** ([#1405](https://github.com/Tochemey/goakt/issues/1405)). The shutdown `PoisonPill` now goes into the mailbox past its capacity.
  - A grain busy under backpressure handles the messages queued before the pill, runs `OnDeactivate` and stops.
  - Before, the pill was rejected with `ErrMailboxFull` and the grain was dropped without `OnDeactivate`.
  - Its queued messages were never handled and `Stop` returned the error.
  - A grain that never finishes its current message is still cut off by the shutdown context.
  - `Stop` now names every grain whose `OnDeactivate` failed in its error; before, that failure was only logged.
- **Grain passivation waits for the message in progress** ([#1397](https://github.com/Tochemey/goakt/issues/1397)). Passivation now always runs on the grain's own turn.
  - A grain without reentrancy was deactivated as soon as it was idle past its timeout, even while `OnReceive` was still running.
  - The next message then started a second instance while the first was still running.
  - Passivation is skipped while messages are waiting in the mailbox.
  - A message that reaches the grain while it deactivates goes to a fresh activation, and its caller gets the reply from it.
  - During a shutdown such a message is refused with `ErrSystemShuttingDown`.
- **A node that is shutting down no longer takes new grains** ([#1396](https://github.com/Tochemey/goakt/issues/1396)). It refuses new activations with `ErrSystemShuttingDown` and keeps serving the grains it has.
  - Before, the registry record of a grain activated late outlived the node.
  - `GrainIdentity`, `GrainOf`, `TellGrain` and `AskGrain` then failed with `remoting is not enabled` for that grain.
  - `GrainIdentity` and `GrainOf` now activate the grain on a live node instead.
  - When they find the recorded owner shutting down or shut down, they release its record right away.
  - `TellGrain` and `AskGrain` with an identity obtained earlier do not release a stale record.
- **A crashed node no longer keeps the names of its non-relocatable actors** ([#1386](https://github.com/Tochemey/goakt/issues/1386)). The leader releases those claims once crash recovery confirms the node is gone.
  - An actor spawned with `WithRelocationDisabled` kept owning its name after its node died without a shutdown.
  - `ActorOf` and `ActorExists` answered with the dead node, and a fresh spawn failed with `ErrActorAlreadyExists`.
  - A spawn that meets such a claim writes its own record over it after checking that its holder is no longer a member.
  - Both are fenced by the actor incarnation, so a name a newer actor already claimed is never removed or written over.
  - Neither actors nor grains of this kind are recreated by the framework; only names and entries are freed.
- **A crashed node no longer keeps the entries of its non-relocatable grains** ([#1386](https://github.com/Tochemey/goakt/issues/1386)). Crash recovery now releases the directory entry.
  - A grain activated with `WithGrainDisableRelocation` kept its entry until the next `GrainIdentity` call.
  - `TellGrain` and `AskGrain` failed against the dead node in the meantime.
  - The next message now re-creates the grain on a live node.
- **Lookups skip non-relocatable actors on departed nodes** ([#1386](https://github.com/Tochemey/goakt/issues/1386)). `ActorOf`, `ActorExists` and `Kill` apply the same membership check.
  - Such an actor reports not found even before the leader releases its claim.
  - Relocatable actors and singletons, which come back under the same name, stay resolvable while they are recreated.
- **Registry read timeouts are distinguishable** ([#1386](https://github.com/Tochemey/goakt/issues/1386)). A timed out read while the cluster converges returns the new `ErrClusterRegistryTimeout`.
  - This applies when the read runs out of its internal timeout while the caller's context is still alive.
  - The error still matches `context.DeadlineExceeded`, so callers can tell it from their own deadline.
- **A spawn no longer fails against a dead node's claim** ([#1391](https://github.com/Tochemey/goakt/issues/1391)). It writes its own record over the claim instead.
  - While the cluster converges, the registry refuses to delete a record while a copy lives on the departed node.
  - A spawn that had to delete the dead node's claim first failed with `ErrActorAlreadyExists`, while `ActorOf` already reported not found.
  - A publication refused because another incarnation owns the name no longer takes the name's lock to find that out.
- **Crash recovery no longer misses a node that died during a rebalance** ([#1387](https://github.com/Tochemey/goakt/pull/1387)). The engine checks the current membership before dropping a departure.
  - The cluster engine defers `NodeLeft` until the routing table has converged on the departure.
  - A rebalance epoch that started before a crash and completed after it still listed the dead node with a newer generation.
  - The engine took the departure for a restart, dropped it and never announced `NodeLeft`, so nothing on that node was recovered.
  - The leader logged only `dropping stale departure`.
  - A member's departure is a stale copy and is dropped as before.
  - A non-member's stays pending until the next convergence without it, or the bounded wait, announces it.
- **Concurrent spawns of one name leave one actor** ([#1377](https://github.com/Tochemey/goakt/issues/1377)). The first spawn wins, and the others fail with `ErrActorAlreadyExists` and leave nothing behind.
  - Two nodes spawning the same name at once could both succeed and keep two live actors.
  - Stopping either deleted the other's registry record.
  - A registry record is now updated or removed only by the actor that owns it.
  - A spawn costs what it did before.
  - Concurrent spawns of different names on one node complete about three times faster, because publishing no longer holds the registry write lock.
  - The new `BenchmarkClusterSpawn` measures both.
- **Actor addresses carry the full path** ([#1379](https://github.com/Tochemey/goakt/issues/1379)). An address renders every ancestor, `goakt://system@host:port/grand/parent/name`, and parses it back.
  - Only the immediate parent used to be written.
  - Two actors nested under same-named parents shared one address, and the second `SpawnChild` returned the first actor.
  - Top-level actors and direct children keep the addresses they had.
  - Large-message destination patterns see the full path, one `*` per segment.
- **Same-named children no longer overwrite or delete each other's records** ([#1380](https://github.com/Tochemey/goakt/issues/1380)). Registry records are keyed by the qualified actor name (`p1/kid`).
  - Two children with the same name under different parents shared one registry record and one local name entry.
  - The second spawn replaced the first, and stopping either deleted the other's record while it was still running.
  - The local name index now keeps every named actor.
  - Top-level lookups are unchanged.
  - A child is found by its qualified name from any node (`ActorOf(ctx, "p1/kid")`).
  - On its own node it is also found by its bare name, which returns the most recently spawned child of that name.
  - A bare-name lookup from another node returns not found.
  - Spawning a top-level actor with the name of a running child now creates the actor.
  - `Reinstate` of a child finds that child.
- **Crash recovery no longer relocates the actors and grains of a node that came back** ([#1383](https://github.com/Tochemey/goakt/issues/1383)). The leader checks the membership before relocating.
  - When a node left without a shutdown snapshot, the leader waited for partition repair to go quiet and relocated what the registry listed.
  - It did not check that the node was still gone.
  - A transient departure, such as a failed and retried bootstrap, had the node rejoin at the same address and keep its actors and grains.
  - They were relocated anyway, leaving two live instances of each.
  - The leader now checks after the wait and again before dispatching, and skips the recovery with a warning when the node is a member again.
  - A node that really crashed is recovered as before.
- **etcd discovery validates `Timeout`** ([#1367](https://github.com/Tochemey/goakt/pull/1367)). A zero `Timeout` is rejected at validation.
  - Before, it passed validation and then failed every etcd request at runtime with an expired context.
  - This is in line with `DialTimeout` and `TTL`.
- **A wildcard bind address listens on every interface** ([#1374](https://github.com/Tochemey/goakt/issues/1374)). `remote.NewConfig("0.0.0.0", port)` now binds the wildcard as configured.
  - Before, it bound the remoting server to one guessed private IP.
  - Connections through loopback or any other interface were refused.
  - Start failed on a host with no private or public address.
  - `::` serves IPv4 and IPv6 peers, and a host with no other address advertises loopback.
  - What peers are told is unchanged: `ActorSystem.Host()`, actor addresses and cluster membership still advertise the first private IP.
  - Cluster gossip and the registry still bind the first private IP.
  - Bind a concrete IP to listen on one interface only.
- **A stopped node stops answering on connections it had open** ([#1396](https://github.com/Tochemey/goakt/issues/1396)). It lets in-flight asks reply, refuses later ones with `ErrRemotingDisabled`, then closes its connections.
  - Before, it answered asks on open connections with `CODE_UNAVAILABLE: tcp: worker pool is stopped`.
  - The sender did not recognize that error, so the registry record of a grain on that node was never released.
  - Every send to that grain failed until the process exited.
  - The sender now releases the stale record and activates the grain on a live node in the same `GrainOf` call.
- **An error answered over a duplex connection keeps its sentinel** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). Both protocols now decode error replies the same way.
  - On the duplex protocol, the default between current nodes, an error reply reached the caller as a plain string.
  - The legacy protocol decoded the same reply to `ErrRemoteSendFailure`, `ErrRemotingDisabled`, `ErrMailboxFull` and the other sentinels.
  - An ask whose connection closes under it fails with a transport error instead of an empty `CODE_INTERNAL` error.
- **A stopping node no longer publishes a grain record** ([#1396](https://github.com/Tochemey/goakt/issues/1396)). A grain recreated during shutdown no longer leaves a record behind.
  - Its registry record could be written after the shutdown had released it.
  - The record then named a node that no longer had the grain.
- **A grain is reachable only once its record is published** ([#1396](https://github.com/Tochemey/goakt/issues/1396)). A message now waits for the activation to complete.
  - An activation whose registry publication failed rolled the grain back with `OnDeactivate`.
  - A message that had reached it in between could still be in `OnReceive`.
  - A failed activation is never seen by a sender.
- **`ORSet` peers no longer lose elements** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). A delta now carries every live element of each node it touches.
  - A delta named a node's whole counter but listed only the elements changed since the last delta.
  - A peer dropped that node's earlier elements, and the next full-state exchange removed them at the origin too.
  - Two consecutive adds by one node were enough.
  - An element added and removed in one update is no longer sent to peers.
- **Anti-entropy repairs values that differ under equal versions** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). The digest now carries a content hash per key.
  - Versions count local events and cannot be compared across nodes.
  - Two nodes holding different values at the same version never exchanged them.
  - State is now exchanged whenever the hashes differ.
  - A merge that changes nothing no longer bumps the version or notifies watchers, so a duplicate delivery counts once.
- **Anti-entropy repairs deletions** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). Live tombstones now travel in both directions of the exchange.
  - A node that missed a deletion was never told of it.
  - After the tombstone expired, anti-entropy brought the key back.
  - When two nodes deleted a key independently, the later deletion is kept.
- **Cross-datacenter replication keeps what it has not delivered** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). Each node keeps one pending entry per key until every datacenter has it.
  - The leader emptied its buffer before sending, so a batch that reached no datacenter was lost.
  - The buffers of other nodes grew with every update.
  - Each datacenter is now sent only what it has not accepted.
  - A key deleted and created again while the deletion was pending is no longer deleted again on the receiving datacenter.
- **`crdt.Changed` carries its key** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). Watchers can tell which key changed.
  - A coordinated read of a key the node did not know no longer breaks its snapshots, including the one taken at shutdown.
- **Compression applies to duplex connections** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). The server now answers the codec it is configured with.
  - The remoting server always answered "no compression" in the duplex handshake.
  - `remote.WithCompression` therefore compressed only legacy connections.
  - Both sides must name the same codec; a mismatch keeps the connection, uncompressed.
  - Closing a compressed connection while a read or a write is in progress no longer panics or hangs.
  - A dialer rejects a handshake reply that names a codec it did not propose.
- **A panic is supervised by the type of the error it carries** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). A panic with an error is matched like `ctx.Err` with that error.
  - A rule for a user error type never applied when the actor panicked with that error.
  - The default `PanicNilError → Restart` rule never fired, so `panic(nil)` stopped the actor.
- **A restart keeps what the actor had** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). Both kinds of restart run `PostStop` then `PreStart` and keep the actor's state.
  - Restarting a running actor told its watchers it had terminated and dropped what it watched.
  - It reset its restart count to one, lost its dependencies and reported an uptime counted from 1970.
  - A supervised restart also ran `PreStart` again without `PostStop`.
  - Restarts now keep the mailbox, the watches, the dependencies and the counters.
  - `Restart` of a stopped actor puts it back in the tree under its parent.
  - A restart that fails for good tells the parent.
- **`Terminated` reaches every watcher, after the name is free** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). It arrives once the dead actor's name can be spawned again.
  - It reaches a watcher that is suspended.
  - It reaches watchers on other nodes.
  - A remote watch, unwatch or reinstate of a child actor resolves it.
  - A node leaving no longer drops the watches of other nodes that share its IP.
- **Passivation no longer races its actor** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). Several races between passivation and the actor are fixed.
  - An attempt that found the actor busy no longer makes it refuse messages and look dead to its parent.
  - A `Shutdown` racing an attempt no longer runs `PostStop` twice.
  - A message accepted just before an attempt is no longer dropped.
  - A deadline no longer fires up to 100 ms early.
  - A deadline expiring during `Stop` no longer makes `Stop` hang.
  - A zero eviction interval no longer crashes the process.
  - Routers no longer passivate after two idle minutes.
- **The scheduler survives its start context** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). Cancelling the context passed to `Start` no longer stops the scheduler while new schedules are still accepted.
  - A fired one-shot now releases its reference.
  - A rejected duplicate reference no longer replaces the listed target.
  - A paused one-shot can be resumed.
- **Routers route as documented** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). Several routing bugs are fixed.
  - Round robin rotates in spawn order.
  - Fan-out keeps each routee's order.
  - A routee that stopped by itself is skipped instead of losing the message.
  - Growing the pool after a removal adds as many routees as asked.
  - Scatter-gather and tail-chopping no longer block the router while they wait.
- **Topics and the event stream** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). Several pub/sub bugs are fixed.
  - Concurrent `TopicStats` on several nodes no longer time out.
  - A topic is removed with its last subscriber.
  - An event-stream subscriber can no longer lose a message or spin under concurrent publishers.
- **Metrics and logging** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). Several metrics and logging bugs are fixed.
  - `ProcessedCount` no longer reads 2⁶⁴−1 before `PostStart`.
  - The dead-letter count is refreshed on every scrape.
  - Metric callbacks are unregistered on `Stop`.
  - Zap error lines carry their stack trace.
  - A file-backed Zap logger keeps flushing after its first `Flush`.
- **Reliable delivery reports a failed load once** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). `ReliableDeliveryFailed` with stage `Load` is published once per failed restart and never during a first spawn.
  - Before, it was published once per `PreStart` retry, during a first spawn too.
  - A data race on the work-pulling controller's generation is fixed.
- **Streams respect downstream demand** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). Stages now pull only what their downstream asked for.
  - Fused stages, `ParallelMap`, `OrderedParallelMap`, `FromChannel` and fan-in inputs pulled ahead of demand without bound.
  - A fan-in input pulls at most one window ahead.
  - A fan-in with as many fast inputs as dispatcher workers no longer freezes the whole actor system.
  - `Batch` emits batches of at most `n`, keeps its last partial batch and fills by size for any `n`.
- **Stream failures and cleanup** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). A failing input fails the stream, and everything a stream started stops with it.
  - A failing or unbuildable input of `Merge`, `Concat`, `Zip`, `Combine` or a `Merge…` variant now fails the stream.
  - The same applies to a substream or a `SourceRef` producer, instead of looking like completion or hanging.
  - The coordinator actor stops with its stream, and a sink crash stops the remaining stages.
  - Inputs, nested streams, substreams and a `SourceRef` source stop with the stream, even when it is aborted right after `Run`.
  - A `First` sink reports an upstream error.
- **Stream builders and fan-out** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). Every `With…` call on a stage now applies, in any order.
  - Before, only the first one did, and the stage lost its actor system, metrics and default name.
  - `Broadcast`, `Balance`, `Partition` and Graph DSL fan-outs can run more than once.
  - `Stop` on a `Broadcast` branch returns, and an aborted branch no longer stalls its siblings.
  - A stage with an error strategy other than fail-fast, or with a tracer, is no longer fused away.

## Deprecations

- **Kubernetes discovery: `RemotingPortName` and `PeersPortName`** ([#1367](https://github.com/Tochemey/goakt/pull/1367)). Both fields are deprecated and ignored.
  - Peers learn these ports from the node metadata exchanged on membership.
  - Existing configurations keep working.

## Documentation

- **Actor lifecycle page** ([#1424](https://github.com/Tochemey/goakt/pull/1424), [#1425](https://github.com/Tochemey/goakt/pull/1425)). The [actor lifecycle page](https://docs.goakt.dev/actor/lifecycle) covers `PostStart` ordering, `PoisonPill` and name release.
  - It states that `PostStart` is delivered before any other message.
  - It describes `PoisonPill` as a priority message handled ahead of the user messages still queued, which are discarded.
  - For a shutdown that first handles everything sent before it, it shows a stop message of your own handled with `ctx.Shutdown()`.
  - It states that the name of a stopped actor is free as soon as the stop returns, in cluster mode too when respawned on the same node.
- **Service discovery page** ([#1367](https://github.com/Tochemey/goakt/pull/1367)). The [service discovery page](https://docs.goakt.dev/clustering/service-discovery) now covers every built-in provider.
  - Each provider has its configuration and a complete example.
- **Streams page** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). `docs/advanced/streams.mdx` is corrected.
  - It no longer lists overflow strategies, a `MicroBatch` field and metric methods that do not exist.
  - It documents the stream behavior above.
- **Runtime pages** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). The remoting, distributed-data, reliable-delivery, supervision, death-watch and passivation pages describe the behavior above.
- **Maintainers' book** ([#1433](https://github.com/Tochemey/goakt/pull/1433)). The design notes in `design/` are replaced by *GoAkt from the Inside*, the maintainers' book in `book/`.
  - It includes an architecture overview (`book/architecture.md`).
  - It has chapters for the dispatcher pool, reentrancy, the remoting transport, reliable delivery, distributed data and reactive streams.
  - It includes the v3 to v4 migration guide (`book/migration/v3-to-v4.md`).
